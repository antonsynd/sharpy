## Design Decisions

1. **One generator, thin lanes (rung: tests only).** `Properties/Generators/Typed/Mutations/` holds
   `AstRewriter` (generic immutable-record rewrite), `MutationSites` (per-position site enumeration over
   `AstDescendants`), `PositionMutations` (per-position one-fact breaks returning `Module`) and `MutationCensus`
   (the 600-sample drawn-code table). `ErrorInjector` stays the ONLY type whose members return an
   `InjectionResult` with a code literal: a new partial file `ErrorInjector.Mutations.cs` holds one member per lane
   (`Inject<Position><Break>[<Family>]`), each a 3–6 line wrapper: choose the site family, call
   `PositionMutations.X`, return `new InjectionResult(mutated, "SPYnnnn")`. *Why:* the roster's link test requires
   the member's body to hold exactly one code literal in the injector file(s); keeping the generator free of code
   literals keeps the code-literal scan rule trivially satisfied and lets one site enumerator serve every lane.
   The link test's `InjectorFile` constant becomes a prefix (`Generators/Typed/ErrorInjector`) so both partial files
   are read.
2. **Site choice is deterministic per sample, varied across samples.** `RunInjectionTest`'s injector signature
   (`Func<Module, InjectionResult?>`) stays; a lane with several applicable sites picks index
   `stableHash(Unparse(module)) % sites.Count` (FNV-1a over the source, never `string.GetHashCode`). *Why:* the P63
   close-out found several lanes draw 2–3 distinct sources in 600 samples because they always mutate the FIRST
   site; a per-sample hash spreads the mutation over the program without changing the driver or CsCheck's
   shrinking. The census prints `distinct mutated sources` per lane as a coverage line (printed, not asserted — it
   is input diversity, not a verdict).
3. **A replacement is always a literal of a type the position refuses, drawn from a fixed table keyed on the
   slot's static type as the GENERATOR knows it** (`TypeEnv` binding / annotation / literal kind): int→`"s"`,
   str→`42`, bool→`"s"`, float→`"s"`, list[T]→`42`, user class→`42`, no-falsy-case→`(1, 2)`. *Why:* the break must
   be ONE fact; an undefined name breaks "defined", a wrong literal breaks "typed" — separate lanes, separate
   codes (SPY0200 vs SPY0222/SPY0220).
4. **`AstRewriter.Replace(root, target, replacement)` is reflection-based over the record's init properties**
   (every property typed `Node`-derived, `ImmutableArray<TNode>`, or a non-node record that holds nodes —
   `ExceptHandler`, `MatchCase`, `FStringPart`, `WithItem`, `Parameter`, `TypeParameterDef`, `KeywordArgument`,
   `DictEntry`, `ElifClause`, `Decorator`, `PropertyObserver`, `UnionCaseDef`), rebuilding the spine from the
   target up by `MemberwiseClone` + init-setter writes, identity-matching the target. Its own falsifiable tests:
   (a) replacing a node with itself yields a structurally equal module (`StructuralEqualityComparer`); (b) every
   node kind reachable from a 200-sample raw corpus of every typed generator member is rebuilt (a kind the rewriter
   cannot re-parent throws, never silently drops — the positive control is a planted `Parenthesized` wrapper around
   each leaf that must survive a round trip); (c) a mutation that deletes the rewritten spine (return the original
   root) turns (a)'s sibling — "replacing a leaf with a different literal changes the unparsed source" — red.
   *Why not hand `with` per kind:* 90+ node records; the injector's four-kind `ReplaceIdentifier` is exactly the
   under-reach this plan drains.
5. **Pins and ByDesign are measured outcomes.** A row flips to `KnownRedRow("#NNNN", observed)` only when the
   census shows every applicable sample analyses clean and `run` is SPY0908 with the named CS code (the P63
   `JudgeSource` pin arm); it flips to `ByDesign(reason)` only when the spec names no refusal for the construct AND
   the census control (the same break) analyses clean — the reason cites the spec line. Today's candidates (hand
   probes; the census confirms): row 57 expression statement (`ByDesign("no typing surface: an expression
   statement admits any expression; every fact inside it is another row's")`), row 34 `x is None` on a non-optional
   (`ByDesign` citing `identity_operators.md` — SPY0349 is `is <Type>`, SPY0465 is value-type identity), row 55
   (`KnownRedRow("#2335", …CS1558)`), row 12 (`KnownRedRow("#2021", …CS1503/CS7036)`), row 19 (`KnownRedRow` on the
   handler-order class issue the lead files — Decision 11).
6. **Cascades are cells, not lane widenings.** A one-fact break that draws two or more codes (measured:
   tuple-pattern arity → SPY0257+SPY0200; positional class-pattern count → SPY0363+SPY0369+SPY0200; generic base
   type-arg arity → SPY0203+SPY0224+SPY0285; `@override` of `@final` → SPY0248+SPY0412) is recorded in the ledger as
   one class — "a refused declaration/pattern cascades into follow-on codes on its own bindings" — and the row uses a
   different one-fact break (tuple arity with an extra element **and an arm body that reads no capture** — measured
   @ 98180fcd9: `case (a, b, _): print(a)` STILL draws SPY0257 + SPY0200 (the leak is the body's read of a capture the
   refused pattern never bound, not the wildcard), while `case (_, _, _): print("m")` and `case (a, b, c): print("m")`
   draw SPY0257 alone [CORRECTED: the wildcard alone does not avoid the cascade]; class pattern on an unknown type → SPY0202;
   generic base with an undefined type argument → SPY0202; `@override` without a base member → SPY0248). `JudgeSource`
   is never relaxed to "contains the code".
7. **The oracle scan becomes rule-based over syntax, and the three name exemptions are deleted** (worklist item 1).
   Rules, each a Roslyn syntax-node visitor over the universe minus the seam files (`ErrorInjector*.cs`,
   `SemanticFilter.cs`, `Mutations/*`, `JudgeSourceTests.cs` as the seam's own tests, the roster's raw-corpus
   runner once it moves into `Generators/Typed/RawCorpus.cs`):
   - **R1 no `catch` outside the seam** — a throw is judged by the seam (`JudgeSource`, `JudgeClean`,
