## Design Decisions

1. **One `CandidateBinding` per candidate, built before applicability.** `BindCandidate(context, candidate)` maps the call's arguments to the candidate's slots — positional by ordinal (variadic absorbs the surplus), keyword by `FindKeywordParameter` (the same two spelling arms as validation, `Calls.cs:3785`), defaults fill the rest, a keyword naming a positionally-filled or positional-only slot marks the candidate inapplicable (C# §12.6.4.2 bullet 2) — yielding an ordered list of `(ArgumentRef, argType, formal)` entries where `ArgumentRef` is `{Ordinal}` or `{Keyword}`. The binding is the ONE input of the type pass, `IsMoreSpecificOverload`, the winner's `BindArgumentsToSelectedOverload`, `RecheckOpenArguments` and the failure record. Axiom 1: this is C#'s "parameter list corresponding to the argument list" (§12.6.2.2).
2. **Inference is part of the binding.** For a generic candidate without written type arguments, the binding's `(argType, formal)` pairs feed `InferTypeArguments` (through a new overload taking the pairs, not the index-aligned list — the index-aligned `:119` entry point stays as the single-candidate route's caller until it too routes through the pairs); success closes the formals (`SubstituteTypeParameters`); failure marks the candidate inapplicable with `OverloadFailureKind.Inference` and the message. A bare value at an open `T?`/`T!E` binds nothing to `T` (P7a's no-binding rule, R-G): the slot closes from its siblings and the value is then judged against the closed `Optional[int32]` — a `Type` failure the seam phrases. An argument whose type is Unknown or a still-unresolved lambda (`FunctionType.HasUnresolvedTypes`) is NEUTRAL: it contributes no inference and no rejection (C# §12.6.3 phase two; the #1589 deferred selection stays as is). The `TypeParameterType` wildcard arm and `ArgMatchesGenericShape`'s role in the type pass are deleted; `OverloadFailureKind.GenericShape` is deleted with them (a shape mismatch IS an inference failure). Explicit type arguments (route 3) and receiver substitutions (`TypeSubstitution`) close the formals before the binding is judged, as today.
3. **Betterness = C# §12.6.4.3, over the binding.** Step A, per bound argument: identity → better conversion target (assignability-directed specificity, `IsMoreSpecificType`, signed-beats-unsigned, the CLR twin) — exactly today's `IsMoreSpecificOverload` body, now iterating the binding. Step B only when step A finds no unique winner.
