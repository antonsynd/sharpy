## Design Decisions

1. **Instrument before cure (both classes).** Phase 0's census guard and Phase 1's invariant land *red* (naming `UnionCasePattern`, and naming the #1727/#1712 fixtures' inverted edges) before any production change; the commit body records the red. This is the P1/P1b/P1c pattern and §2 of the contract.
2. **Structural precedence invariant + reparse cross-check, not reparse alone.** The standing guard is a built-tree walk (`EmittedTreePrecedence.Violations`) against an explicit C# precedence/associativity table (ECMA-334 §12.4.2 plus the parser disambiguation rules Roslyn applies). It is O(n), corpus-independent, runs on every unit-test emission, every fixture and stdlib unit, and in production (Decision 4). Because the table is hand-written, it is **verified as an instrument** (§5) against Roslyn's own parser: for every corpus expression, `ParseExpression(NormalizeWhitespace().ToFullString())` has the same kind-shape as the built node ⟺ `Violations` is empty (with the one known benign difference the reparse guard already documents: a `QualifiedNameSyntax` callee vs. `SimpleMemberAccessExpression`). Any other disagreement is a table bug and blocks the phase. [VERIFIER NOTE: a disagreement in which `Violations` is empty but the reparsed shape differs by a **non-precedence** mechanism — token adjacency such as `- -x` printing as `--x`, or the generic-call ambiguity `a < b > (c)` — is a sibling class of the same contract (the emitter already carries one such text-level patch, `DeconstructionSpacingRewriter` at `RoslynEmitter.CompilationUnit.cs:196–200`); file it as an issue and roster it, do not widen the precedence table to absorb it.] Reparse-only guarding was rejected: it is corpus-bound, costs a parse per unit, and (per plan-f08ccf's finding) `IsEquivalentTo` at unit level is unusable — the expression-level kind-shape comparison here is the narrow form that is usable.
3. **One `Operand(child, parentKind, slot)` seam; migrate the seams that wrap generated expressions; the invariant guards the rest.** ~700 raw factory sites exist; most take identifiers, literals or invocations (primary — can never invert). The plan migrates every truthiness arm and every site whose operand is a generated expression at the enumerated families (casts, member access on generated receivers, `is`-pattern subjects, prefix unary, `??`, conditional tests, `await`), enumerated by the corpus invariant plus a grep audit (recipe in Task 2.2). A file-wide scan-ratchet banning raw factory calls was considered and **not** adopted: with `MemberAccessExpression(` at 230 sites the ratchet would be mostly noise, while the invariant already makes a new inverted site fail on the first program that reaches it, in whichever project compiles it. `/verify-plan` may overrule this.
4. **A production net, SPY0524 `EmittedTreePrecedenceInversion` (CodeGen range, Error).** `CompilerInvariants` runs the same walk on the emitter's unit at both production `GenerateCompilationUnit` call sites (`ProjectCompiler.CodeGen.cs:102`, `ProjectCompiler.Generators.cs:175`) before the ParseText branch. Rationale: the ILCompiles fresh-seed sweep and every downstream project then name the *class* ("unparenthesized ConditionalExpression operand of SimpleMemberAccessExpression at …") instead of a CS0173 behind SPY0908. Cost is one tree walk per unit. Landing order: after Phase 2 has emptied the corpus, so the net fires on nothing in the gate. Rule 10: `DiagnosticExplanations` entry + explanation-test coverage. SPY0524 is the next free CodeGen code (0500–0508, 0510, 0518–0523, 0550–0555, 0599 taken) [verified: `DiagnosticCodes.cs:852` reserves 0524–0549 for future codegen diagnostics; SPY0521 is a reserved-not-active constant that nevertheless carries an explanation entry].
5. **The reparse guard becomes bidirectional and asserts failing-C#-compile units.** `ExtraBindingErrors` reports diagnostics in *both* directions (a reparse-side-only diagnostic means the printed text does not mean what the tree means — and production compiles the text). `CompileFixture` hands back units whenever the Sharpy front end reported no error (i.e. codegen produced a unit) even if the C# stage then refused it — those units are exactly the class's members. The symmetric diff needs a reparse compile on every unit; the implementer measures the added wall-clock on the fixture arm and, if it exceeds +60 s, moves the symmetric arm under `[Trait("Category","GapDiscovery")]` (precedent: the three CI sweeps) while the O(n) `Violations` walk stays in the default run.
6. **#1712 acceptance is "runs", not "emits `x is T`".** With `Operand`, the coercion-truthiness tree prints as `(o is long __t ? Optional<long>.Some(__t) : default).IsSome`, which is valid C# (`Optional<T>` is a struct; the `default` literal is target-typed by the other branch). The `x is T` optimization stays with Batch 6b (#1713) per the owner's re-batching. R-F stands.
7. **#1730: delete; the class guard is a Roslyn *semantic* scan.** A text scan cannot do this job: `Parser.Ast.TupleType` (a non-`Node` record in `Types.cs:106`) and `Semantic.TupleType` share a name (17 `new TupleType` sites in `src/Sharpy.Compiler`+`src/Sharpy.Lsp`, all `Semantic.TupleType`; 25 counting tests) — and `Parser.Ast.TupleType` itself is a dead kind Phase 0 Task 1 deletes [CORRECTED]. The guard binds every object-creation expression in a `CSharpCompilation` over `src/Sharpy.Compiler` (+ `src/Sharpy.Lsp` for the roster arm) — the recipe `DispatchSiteScan` already implements (GlobalUsings + `SharpyRT` alias; `unresolved == 0` asserted, memory `reference-roslyn-source-compilation-scan`). Universe = reflection over every concrete public record type in the `Sharpy.Compiler.Parser.Ast` namespace (not just `Node` subtypes — 11 AST records such as `WithItem`, `ExceptHandler`, `MatchArm` and `TupleType` are plain records the parser also constructs); the scan binds object creations to symbols in that namespace, which is what disambiguates the `TupleType` collision. Roster of kinds synthesized outside `Parser/` with a **checked** justification (the kind must have ≥ 1 site in the named file) — exemption-not-subject. The generators' construction universe must be ⊆ (parser-constructed ∪ roster). The record is deleted rather than wired because the parser already represents union-case matches as `PositionalPattern` (measured) and the spec never names a distinct form.
8. **Rule 2 is untouched.** `Operand`/`EmittedTreePrecedence` decide from C# `SyntaxKind` facts only — no Sharpy type, no `SemanticInfo` read. The truthiness *kind* still comes from the materialized `TruthinessLowering` tag. `EmitterCarrierOnlyConformanceTests` needs no roster change (the new file names no `Semantic` type); the implementer runs it as part of the gate.
9. **Axioms:** Axiom 1 (.NET) governs the implementation (C# grammar is the authority for the table); the user-facing surface is unchanged. No spec change: `type_casting.md` and `boolean_context`/truthiness sections already describe the intended behavior — the executed fixtures are the spec evidence (Rule 7 satisfied by execution, not by prose).
