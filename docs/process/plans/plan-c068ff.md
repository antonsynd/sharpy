## Context

Three open groups share one defect: **an operand with no type of its own reaches a place that must give it one, and nothing decides.** Bare `None` (a `VoidType` in the checker) and a void call bind a fresh name through the walrus and tuple-unpacking routes (#1812, #1516's twin routes), type a tuple element as `void` (#1796), and make a slot-less `[None, 1]` an `object` list; two conditional branches with unrelated types are typed `Unknown` behind a DeliberatelyPermissive mark and printed as a raw C# ternary (#1677, #1743); five literal sites and one pattern site join element types through a least-common-ancestor walk R-W retired (`FindLeastCommonAncestor`, six callers); six data-level `IsAssignableTo` sites still bypass the checker's one assignability authority (#1748). The ILCompiles property sweep drew seed `2hN1ZVOkyIgJ` in the P7a closing gate and turned the gate red on #1812's cell — the one red of `28,580/1/5 @ 8155b46e4`.

R-W (2026-09-05) states the one rule that replaces all of them — C#'s best-common-type (§12.6.3.15 / §12.18): (1) a slot decides when there is one, each operand admitted or refused at ITS span by the store seam; (2) else one operand's own type must implicitly accept every other and that is the type; (3) else refuse by name with an annotate-the-target steer. R-AB adds that a bare `None` is untyped in that rule (a slot-less literal or conditional containing one is an arm-3 refusal). R-AE adds that a fresh walrus directly under a store slot takes the slot's type, elsewhere is refused exactly like `x = None`, and a void-call walrus is refused everywhere. #1516's `x = None` refusal is therefore the single-operand, slot-less case of the same rule, and this plan builds that ONE helper, folds the #1516 arms into it, and migrates every operand-join site to it. The chore #1794 (R-AC) rides in front as Phase 1: the const-host axis of plan E has three cells nobody computed (synthesized struct constructor roster, all-const struct, interface host).

## Design Decisions

1. **One helper, one file, one signature (R-W; P9 consumes it).** `src/Sharpy.Compiler/Semantic/TypeChecker.BestCommonType.cs` (partial `TypeChecker`, because arms 1–2 go through `IsAssignable`/`ClassifyStore`/`CheckStore`):
   ```csharp
   /// The R-W rule. Operands carry their node when they have one (a spread element has none).
   /// Returns the decided type, or Unknown after reporting exactly one diagnostic.
   internal SemanticType BestCommonType(
       IReadOnlyList<(Expression? Node, SemanticType Type)> operands,
       SemanticType? slot,            // null = slot-less
       StorePosition position,        // the position each operand is admitted at under arm 1
       Node host,                     // where an arm-3 refusal is lodged (the literal / conditional / binding)
       string siteNoun,               // "list", "tuple element 1", "conditional expression", "binding 'x'", …
       BestCommonTypeOptions options = default)   // TruthinessPosition (Phase 3), AnnotateSteer(string)
   ```
   Arm 1 (slot non-null): every operand with a node is `CheckStore(position, node, type, slot, host, node.Span)` — refused at ITS span with the seam's own code (SPY0220 / SPY0229 / SPY0604 …); a node-less operand is `IsAssignable`; the result is the slot; the existing `AdmitCollectionElements` / `AdmitTupleElements` are the arm-1 implementation for literals (they already call `ClassifyStore` per element) and are NOT duplicated — `BestCommonType` calls them. Arm 2 (slot-less): candidates are the operand types that are neither `VoidType` nor `UnknownType`; a candidate wins when every other operand is admitted into it (through `ClassifyStore` when a node exists, so `[1, 2.5]` → `float` and `[1, 10000000000]` → `int64` by the constant arm; `IsAssignable` otherwise); exactly one canonical winner (`CanonicalKey`) → that type; several distinct winners → arm 3 (C#'s ambiguity rule). Arm 3: SPY0227 (`CannotInferType`, reused per charter §6 — no new code) lodged on `host`: `cannot infer a type for <siteNoun>: its operands have no best common type (<t1>, <t2>) — annotate the target (e.g. '<steer>')`, the steer supplied by the caller (`xs: list[object] = …`, `a: Animal = …`, `x: T | None = …`). **None operand (R-AB (i)):** a `VoidType` operand whose node is a `NoneLiteral` is untyped — slot-less it is always arm 3 with the `T | None` steer (`'x: int | None = …'`), single operand included (`x = None`: `'None' names no type on its own, so 'x' has nothing to be. Annotate the binding ('x: T | None = None' for a .NET-nullable reference; 'x: T? = None()' for a Sharpy optional)`); under a slot it is a store the seam decides (SPY0229 into a non-nullable, SPY0604 into `T?`, accepted into `T | None`). A `VoidType` operand whose node is NOT a `NoneLiteral` (a void call) is refused in every arm with #1516's second reason (`produces no value`), slot or not (R-AE). `UnknownType` operands propagate Unknown silently (error recovery). Single-operand degenerate case = the fresh-binding seam (Decision 2).
