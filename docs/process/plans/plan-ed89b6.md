## Design Decisions

Every decision below is test infrastructure; the layer-ladder rung question ("where does the behaviour live?") applies to the **oracle**, not to a compiler seam: the oracle is **rung 1 — a Sharpy source and its python twin** rendered from one cell model, never a name-keyed rule reading the compiler's tables (the expectation function is the harness's OWN literal copy of N1–N7, as `StaticInitializerOrderMatrixTests.OrderCell` is of R-JT).

**D1. One cell model → one Sharpy source → one python twin (`TwinRenderer` is a Sharpy-AST → python translator).** A cell is a record (family, axis values, the distinct literal value of every binding it declares). The generator renders it to Sharpy SOURCE first; the python twin is then produced from that source by parsing it with the compiler's own parser (`Sharpy.Compiler` `Lexer` + `Parser`, no semantic pass) and walking the AST through ONE per-construct table — not a regex over text. The SAME walk renders a seed `.spy` file (D7), so `renderer(seed.spy)` and the generated cells' twins share one path and the seed's hand twins guard the table that every generated twin uses (the inventory's `auto_py` regex is replaced, not ported). The table: `@static` line dropped / `@static def` → `@staticmethod`; `const`/`let`/`var` keyword stripped; `property NAME: T = v` → `NAME = v`; `struct` → `@dataclass class` (a struct's fields are constructor parameters with defaults, L13 — python's dataclass is the twin that constructs the same way); `@dataclass` adds `from dataclasses import dataclass`; `type A = H` → `A = H`; function-style accessors `property get NAME(self) -> T:` → `@property` + `def NAME(self):` and `property set NAME(self, v: T):` → `@NAME.setter` + `def NAME(self, v):` (`properties_function_style.md`); `global`/`nonlocal` kept verbatim; the `out let` pair — callee `def f(out v: int) -> None: v = 15` and call `f(out let v)` — → `def f(): return 15` and `v = f()` (`parameter_modifiers.md`: python's idiom for an `out` parameter is a return; the model's value is the local's 15); `case P as v:` and `case Later():` verbatim (python 3.10 pattern syntax); `o as? Later` → `(o if isinstance(o, Later) else None)` and `o as! Later` → `o` (a cast carries no name verdict beyond the type position; the twin keeps the value); a user context manager's `def __exit__(self) -> None:` → `def __exit__(self, exc_type, exc, tb):` (`context_managers.md`: Sharpy's `__exit__` takes no arguments, python passes three — a verbatim twin raises `TypeError: CM.__exit__() takes 1 positional argument but 4 were given`, probed 3.12.13) with `__enter__` verbatim; `enum E:` → `from enum import Enum` + `class E(Enum):` (cases, `.value`, `.name` verbatim); `interface I:` → `class I:` with its `def m(self): ...` bodies kept and an implementing `class C(I)` verbatim; `union U:` with `case V(f: T)` / `case L()` → `class U: pass` + one `class V(U)` per case carrying `__match_args__ = ("f",)` and an `__init__`, then `U.V = V` so the qualified construction `U.V(3)` (`tagged_unions.md:180`'s spelling) and the bare pattern `case V(v):` both work (probed: prints `3`); a TYPEMEMBER cell whose scrutinee is a `T?` member gets a four-line `class Some` shim with `__match_args__ = ("value",)` prepended and `case _:` as the second arm in BOTH twins (probed: prints `1`; the `case None():` arm is excluded axis (vii)); `main()` appended; **every annotation is STRIPPED** — `x: T = v` → `x = v`, `def f(p: T) -> R` → `def f(p)` — EXCEPT inside a `@dataclass`/`struct` body, where python's dataclass needs the field annotation and the table maps the Sharpy type to a python spelling (`int`/`float`/`str`/`bool` verbatim; anything else — `() -> int`, `T?`, `list[…]`, a user type — `object`). *Why strip:* Sharpy's `() -> int`, `T?` and `list[() -> int]` are not Python syntax (the inventory hand-wrote the E06/D10/C43 twins for exactly that reason), python evaluates module-level annotations eagerly (so an annotation naming a later class would add an unmodelled `NameError`), and no cell's VALUE depends on an annotation; the one place an annotation carries meaning in python is the dataclass field, which is why that is the one exception. Every declared value is distinct (P75's convention: e.g. `@static` field 2, `@static` property 4, computed const 7 via `seven()`, literal const 1, `@static` method 6, instance field 3, module var 5, module property 8, module literal const 9, module computed const 11, enclosing local 13, local 15; an uninitialized read is `0`; D3.b's form table adds module `def` call 12, class constructor field `.v` 14, struct constructor field 19, enum case `.value` 16, union case payload 17, interface through its implementing class 18, nested type constructor field `.v` 20) so a wrong binding, a CLR default or a skipped initializer each print a different number.
