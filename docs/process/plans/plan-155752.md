# NumPy-Equivalent Module (`numpy`) for Sharpy.Core

## Context

Python developers coming to Sharpy instinctively reach for `numpy` for numerical/array operations. This plan adds a `numpy` module to Sharpy.Core that provides a familiar NumPy-like API backed by [Math.NET Numerics](https://numerics.mathdotnet.com/) where appropriate and handrolled implementations otherwise.

GitHub issue: [#646](https://github.com/antonsynd/sharpy/issues/646)

## Current State

- No `numpy` module, `ndarray` type, or Math.NET dependency exists in the codebase.
- The stdlib already has `math`, `statistics`, and `random` modules that cover scalar operations. `numpy` fills the gap for vectorized/array operations.
- The `[SharpyModule]` / `[SharpyModuleType]` discovery system handles all registration automatically. No compiler changes are needed. [CORRECTED: While the discovery infrastructure handles generic types (used for List/Dict/Set), no existing `[SharpyModuleType]`-decorated type is generic. The code paths support it (OverloadIndexBuilder discovers generics, CachedModuleDiscovery creates TypeParameterType instances), but this combination is untested. Phase 1 Task 2 should validate this early.]
- Submodule pattern exists via `[SharpyModule("os.path")]` — reuse for `numpy.linalg`, `numpy.random`, `numpy.fft`.
- Sharpy.Core multi-targets `net10.0;netstandard2.1`. Math.NET Numerics supports `netstandard2.0+`, so it's compatible with both targets.

## Design Decisions

### 1. ndarray as a Generic Class

```csharp
[SharpyModuleType("numpy", "ndarray")]
public class NdArray<T> where T : struct, IEquatable<T>
```

- **Axiom 3 (Type safety)**: Generic `ndarray[T]` provides compile-time element type checking, unlike Python NumPy's runtime dtype. Users write `ndarray[float]`, not `ndarray` with a runtime dtype parameter.
- **Axiom 1 (.NET)**: `where T : struct` leverages .NET value types for performance. Row-major layout over a flat `T[]` buffer.
- **Axiom 2 (Python)**: API naming mirrors NumPy (`zeros`, `ones`, `reshape`, `transpose`).

### 2. Backed Storage

Flat `T[]` buffer with shape/stride arrays. Row-major (C order) by default, matching NumPy's default. Views (slices, transpose) share the underlying buffer with different strides — no copy unless explicitly requested.

### 3. Math.NET Integration

| Category | Backend | Rationale |
|----------|---------|-----------|
| Linear algebra (dot, inv, det, eig, svd) | Math.NET `Matrix<double>` / `Vector<double>` | Proven, optimized LAPACK bindings |
| Array creation (zeros, ones, arange, linspace) | Handrolled | Trivial; avoids unnecessary Math.NET coupling |
| Element-wise ops (+, -, *, /, sqrt, exp) | Handrolled with `Span<T>` | Better perf for simple ops; no matrix overhead |
| Statistical (mean, std, var, median) | Handrolled | Small functions; `statistics` module already has patterns |
| Random distributions | Math.NET `MathNet.Numerics.Distributions` | Well-tested distribution implementations |
| FFT | Math.NET `MathNet.Numerics.IntegralTransforms` | Standard FFT implementation |

### 4. Submodule Structure

```
numpy              → [SharpyModule("numpy")]     class Numpy
numpy.linalg       → [SharpyModule("numpy.linalg")]  class NumpyLinalg
numpy.random       → [SharpyModule("numpy.random")]  class NumpyRandom
numpy.fft          → [SharpyModule("numpy.fft")]      class NumpyFft
```

### 5. Operator Overloading

`NdArray<T>` implements `operator+`, `operator-`, `operator*`, `operator/` for element-wise operations. These are .NET operator overloads, not dunder methods — `ndarray` is a Sharpy.Core type, not a user-defined class.

### 6. Broadcasting

Broadcasting follows NumPy rules: trailing dimensions are aligned, dimensions of size 1 are stretched. Implemented as stride manipulation (no data copy) where possible, falling back to explicit expansion for non-contiguous cases.

### 7. C# 9.0 Constraint

Sharpy.Core's `netstandard2.1` target requires C# 9.0. This means:
- No file-scoped namespaces
- No `required` keyword
- No generic math interfaces (`INumber<T>`)
- Element-wise math dispatched via runtime type checks or overloads for `double`/`float`/`int`/`long`

Use `#if NET10_0_OR_GREATER` for C# 14-only optimizations (e.g., generic math). [CORRECTED: `Span<T>` is available in netstandard2.1 natively — it does NOT require gating. Only newer Span-related APIs or generic math interfaces need the `#if` gate. `System.Numerics.Complex` is also available in netstandard2.1 without gating (already used by `Sharpy.Core/Partial.Complex/Complex.cs`).]

### Phase 1: Foundation — NdArray Type and Array Creation

**Goal:** Core `NdArray<T>` type with shape/stride layout, basic indexing, and array creation functions.

#### Tasks

1. **Add Math.NET Numerics dependency** — `src/Sharpy.Core/Sharpy.Core.csproj`

2. **Create NdArray<T> core type** — `src/Sharpy.Core/Numpy/NdArray.cs`
   - Flat `T[]` buffer, `int[] Shape`, `int[] Strides`, `int Offset`
   - Constructor: `NdArray(T[] data, int[] shape)` + internal `NdArray(T[] data, int[] shape, int[] strides, int offset)` for views
   - Properties: `Ndim` (rank), `Size` (total elements), `Shape` (as tuple), `Dtype` (typeof(T).Name mapped to numpy name)
   - Row-major stride computation: `ComputeStrides(int[] shape)` → strides array
   - Decorate with `[SharpyModuleType("numpy", "ndarray")]`
   - Commit: `feat(core): add NdArray<T> core type with shape/stride layout (#646)`

3. **Scalar and flat indexing** — `src/Sharpy.Core/Numpy/NdArray.Indexing.cs`
   - `this[params int[] indices]` getter/setter — multi-dimensional indexing
   - Internal `GetOffset(int[] indices)` — converts N-D indices to flat buffer offset using strides
   - Bounds checking with `IndexError` for out-of-range
   - Negative index support (Python semantics: `-1` = last element)
   - Commit: `feat(core): add NdArray multi-dimensional indexing (#646)`

4. **Slice indexing (views)** — `src/Sharpy.Core/Numpy/NdArray.Slicing.cs`
   - `Slice(SliceSpec[] slices)` — returns a view (shared buffer, adjusted strides/offset)
   - `SliceSpec` struct: `Start`, `Stop`, `Step` (nullable ints, matching Python slice semantics)
   - Row/column selection: `GetRow(int i)`, `GetColumn(int j)` returning 1-D views
   - Commit: `feat(core): add NdArray slice indexing with views (#646)`

5. **Create numpy module and array creation functions** — `src/Sharpy.Core/Numpy/__Init__.cs`, `src/Sharpy.Core/Numpy/Numpy.cs`
   - `__Init__.cs`: `[SharpyModule("numpy")] public static partial class Numpy { }`
   - `Array(T[] data)` → 1-D ndarray
   - `Array(T[,] data)` → 2-D ndarray
   - `Zeros(params int[] shape)` → ndarray filled with 0.0
   - `Ones(params int[] shape)` → ndarray filled with 1.0
   - `Full(int[] shape, T value)` → ndarray filled with value
   - `Eye(int n)` → n×n identity matrix
   - `Arange(double start, double stop, double step = 1.0)` → 1-D ndarray
   - `Linspace(double start, double stop, int num = 50)` → 1-D ndarray of evenly spaced values
   - `Empty(params int[] shape)` → uninitialized ndarray (default values)
   - Commit: `feat(core): add numpy module with array creation functions (#646)`

6. **Reshape, transpose, flatten** — `src/Sharpy.Core/Numpy/NdArray.Reshape.cs`
   - `Reshape(params int[] newShape)` — returns view if contiguous, copy otherwise. One dimension can be `-1` (inferred).
   - `Transpose()` / `T` property — returns view with reversed strides (no copy)
   - `Flatten()` — returns 1-D copy
   - `Ravel()` — returns 1-D view if contiguous, copy otherwise
   - `Copy()` — deep copy
   - Commit: `feat(core): add NdArray reshape, transpose, flatten (#646)`

7. **String representation** — `src/Sharpy.Core/Numpy/NdArray.Display.cs`
   - `ToString()` — NumPy-style formatted output (e.g., `array([1, 2, 3])`, `array([[1, 2], [3, 4]])`)
   - Truncation for large arrays (threshold at 1000 elements, show first/last 3 along each axis)
   - Commit: `feat(core): add NdArray string representation (#646)`

- Scalar (0-D) arrays
- Very large arrays (memory)

- Broadcasting dimension mismatches → `ValueError`
- Singular matrices → appropriate Math.NET exceptions wrapped as `ValueError`
- Integer overflow in shape computation
- NaN/Inf propagation in arithmetic

### Warnings

1. **Generic module type discovery is untested territory** — The plan's core type `NdArray<T>` with `[SharpyModuleType("numpy", "ndarray")]` would be the first generic module type in the codebase. Discovery infrastructure supports generics (via `IsGenericTypeDefinition` checks in `CachedModuleDiscovery`), but this specific path has no existing precedent. **Recommendation:** Add a validation step early in Phase 1 — create a minimal `NdArray<T>` skeleton, build, and test `import numpy; x: ndarray[float] = np.zeros(3)` end-to-end before proceeding with the full implementation.

2. **Thread safety for `numpy.random`** — The plan's `Seed(int seed)` implies global mutable state. This matches Python NumPy's behavior (not thread-safe), but should be documented. Consider using `[ThreadStatic]` for the RNG instance.

3. **Package size impact** — Math.NET Numerics is a substantial dependency. The csproj currently has only 3 package references. This is an acceptable trade-off for the functionality provided, but worth noting.

4. **Operator overloads are type-specific** — The plan correctly defines operators on `NdArray<double>` (not generic `NdArray<T>`). In C# 9.0, generic operator overloads require concrete type parameters. Users wanting `NdArray<float>` arithmetic would need separate overloads or explicit conversion. The plan should clarify which element types get full operator support.
