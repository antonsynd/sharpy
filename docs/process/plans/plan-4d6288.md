## Context

`sharpyc format` (and the LSP formatting handlers, which call the same `FormatterService.Format`) rewrites a file IN PLACE. Four open issues show it changing what the program means or destroying user text:

- **#2062** (class tracker) — trailing whitespace stripped INSIDE triple-quoted strings (`"""p  \nq"""` printed `p` instead of `p__` after formatting). Silent wrong.
- **#2068** — a statement's trailing comment inserted INSIDE a multi-line string literal (changes output); a comment after a statement ending inside a string dropped. Silent wrong.
- **#2077** — a comment inside a bracketed expression is dropped (`xs = [1,  # inner\n 2]` → `xs = [1, 2]`). Silent wrong (user text destroyed; program output unchanged).
- **#2157** (class tracker) — the backtick escape on a keyword-argument name is dropped: `` f(`class`=7) `` formats to `f(class=7)`, which does not parse. The formatter turns a valid file into an invalid one.

The contract the group enforces (charter §3.11): **`sharpyc format` never rewrites bytes inside a string token and never drops a comment or an escape: `format ∘ run ≡ run`, `Format(P)` re-parses to an AST structurally equal to `P`'s, and the comment sequence and the escaped-name multiset of `P` equal those of `Format(P)`.**
