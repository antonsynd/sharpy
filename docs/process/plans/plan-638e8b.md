## Design Decisions

**D1 — one Core classifier for (path state × what the operation requires) → `OSError` subclass (rung 2).** A static Core helper (callable from spy sources by `from sharpy import …`, the spelling the spy modules already use for Core types) with two doors that share one table: *check(path, requirement)* for operations where .NET is silent or lenient and POSIX refuses (`File.Delete` on a missing path, `Directory.CreateDirectory` on an existing one or with a missing parent), and *translate(clrException, path, requirement)* for a caught `IOException` family member or `UnauthorizedAccessException`. The requirement is a closed enum (needs-file-to-read, needs-file-to-write, creates-exclusively, removes-file, creates-dir, removes-dir, needs-dir, needs-any). The table is python's errno rule spelled once: missing or missing parent → `FileNotFoundError`; a parent that is a file, or a directory required and a file found → `NotADirectoryError`; a file required and a directory found → `IsADirectoryError`; create onto anything existing → `FileExistsError`; remove of a non-empty directory → plain `OSError`; an access refusal with none of those states → `PermissionError`; any other CLR I/O failure → plain `OSError`, never a CLR type. `open()` in `src/Sharpy.Core/Open.cs` (the `catch` ladder at `Sharpy.Core/Open.cs:83`) becomes the first caller, so the W1.7 cells are the helper's positive control. Every Stdlib module site — handwritten C# and spy — calls the helper and stops spelling a subclass. Why not rung 1: 8 handwritten C# files and Core's `open()` need it too, and one table in two languages is two tables. Why not rung 3/4: no compiler fact is involved. **Three predicates the first pass added:**
  1. *Translate is idempotent.* Core `OSError` derives from `System.IO.IOException`, so an outer `catch` receives exceptions the helper already classified; *translate* returns an `OSError` instance unchanged (the guard `Sharpy.Core/Open.cs:91` has today).
  2. *Two-path operations.* A rename is ONE POSIX call and python's verdict is a function of the PAIR of states, not of each position (measured, the base table), so the helper has a pair door for the rename requirement and the enum has that member. `shutil`'s copy, move and tree operations are python-level sequences of single-path steps; the spy module spells the same steps in CPython's order, each step one single-path helper call, and never a pair table of its own. The enum is closed and its member list belongs to the code: this plan carries no count, and R1 reads it with `Enum.GetValues`.
  3. *Python succeeds where .NET refuses* (`os.rename` onto an existing file; POSIX `rename` replaces). This is not a table arm. The call site uses the .NET overload with POSIX semantics (`File.Move` with `overwrite: true`), so no exception exists to translate; G1's rule already makes the cell red while the raise remains.

**D2 — Core gains `NotADirectoryError(OSError)` and nothing else (rung 2).** Six measured cells need it and python's tree has it; it gets a row in the "Exception Type Hierarchy" table of `docs/language_specification/exception_handling.md` (an addition the charter's contract rules — python's tree — not a spec edit to match a wrong implementation) and is measured automatically by `ExceptionHierarchyPythonMroTests` (reflection-generated rows). The `### OSError` prose under that table (`docs/language_specification/exception_handling.md:42`) names the four subclasses and says "all four"; it is edited with the row. **Ruled:** the name becomes reserved, so a user `class NotADirectoryError` is SPY0212 from this change on — `worked` → refused, accepted by the owner on 2026-11-10 ("Add it") as the consequence every builtin exception name already has; the escape is the backtick spelling SPY0212's message offers. NOT added here: `TimeoutError` (only useful with D3's identity, and it refuses a user class a fixture declares) and the `ConnectionError` family (`src/Sharpy.Stdlib/Requests/Exceptions.cs:43` already declares `Sharpy.ConnectionError` for `requests`; a Core type of the same full name is a CLR collision). Both go to the ledger as cells for the lead.

**D3 — socket exceptions derive from `OSError` in the spy source; the identity is a deviation row (rung 1, as the owner ruled).** Rung 1 was tried @ 2c803eb32: `type error = OSError` in a module gives the full identity for a SOURCE import (`except lib.error` catches a plain `OSError`, `type()` prints `OSError`; two-file project, run), but a compiled library emits no member for an alias (`docs/language_specification/type_aliases.md`: "emits no runtime member"; the library C# has no `error`), and Stdlib is consumed compiled: discovery reads only `[SharpyModuleType]`-stamped CLR types (`OverloadIndexBuilder.cs:58`), and that attribute is `AllowMultiple = false` and assigns the type to the named module instead of its namespace (read at `OverloadIndexBuilder.cs:482`, not run), so stamping Core `OSError` is not available. The identity therefore needs a module-export alias in `Discovery/` + `Semantic/Registry/` (W1.7's shape on the module table) — a compiler seam, outside this tier. In tier: `src/Sharpy.Stdlib/spy/socket_module.spy:72` becomes `class error(OSError)` (probe: an `OSError`-derived class with an `errno` field compiles and is caught by `except OSError` and `except IOError`); `timeout`, `gaierror`, `herror` keep deriving from `error`, so `issubclass(gaierror, OSError)` holds and `except socket.error` still catches a timeout (#945's fixture). The residue is ONE `docs/deviations.yaml` row (`socket-error-timeout-distinct-classes`): `type(socket.error(..))` spells `socket.error`; `except socket.error` does not catch a non-socket `OSError`; `socket.timeout` is not `TimeoutError`. The row names the module-export alias as its removal path.

**D4 — one table, and its reference host is Linux (test and docs; no rung).** The helper's table is python3's verdict on Linux (the kernel's errno). G1's differential runs where that is the oracle's host: on Linux it runs python (CI's ubuntu job sets `SHARPY_REQUIRE_PYTHON_ORACLE=1`, so the gate cannot skip it); on any other host the differential is SKIPPED with that reason, while T1–T5, R1–R2, A2 and A3's roster checks need no python and run everywhere. Known and unmeasured (no macOS host in either session): POSIX `unlink` on a directory is `EPERM` on macOS, where python raises `PermissionError`; Sharpy there raises the Linux class. That is a ledger cell for the lead (a deviation-row candidate), not an assertion. Why not a table per host: two tables is the class this plan removes.
