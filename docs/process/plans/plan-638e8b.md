## Design Decisions

**D1 — one Core classifier for (path state × what the operation requires) → `OSError` subclass (rung 2).** A static Core helper (callable from spy sources by `from sharpy import …`, the spelling the spy modules already use for Core types) with two doors that share one table: *check(path, requirement)* for operations where .NET is silent or lenient and POSIX refuses (`File.Delete` on a missing path, `Directory.CreateDirectory` on an existing one or with a missing parent), and *translate(clrException, path, requirement)* for a caught `IOException` family member or `UnauthorizedAccessException`. The requirement is a closed enum (needs-file-to-read, needs-file-to-write, creates-exclusively, removes-file, creates-dir, removes-dir, needs-dir, needs-any). The table is python's errno rule spelled once: missing or missing parent → `FileNotFoundError`; a parent that is a file, or a directory required and a file found → `NotADirectoryError`; a file required and a directory found → `IsADirectoryError`; create onto anything existing → `FileExistsError`; remove of a non-empty directory → plain `OSError`; an access refusal with none of those states → `PermissionError`; any other CLR I/O failure → plain `OSError`, never a CLR type. `open()` in `src/Sharpy.Core/Open.cs` (the `catch` ladder at `Sharpy.Core/Open.cs:83`) becomes the first caller, so the W1.7 cells are the helper's positive control. Every Stdlib module site — handwritten C# and spy — calls the helper and stops spelling a subclass. Why not rung 1: 8 handwritten C# files and Core's `open()` need it too, and one table in two languages is two tables. Why not rung 3/4: no compiler fact is involved. **Predicates 1–3 came from the first pass, 4 from the second:**
  1. *Translate is idempotent.* Core `OSError` derives from `System.IO.IOException`, so an outer `catch` receives exceptions the helper already classified; *translate* returns an `OSError` instance unchanged (the guard `Sharpy.Core/Open.cs:91` has today).
  2. *Two-path operations.* A rename is ONE POSIX call and python's verdict is a function of the PAIR of states, not of each position (measured, the base table), so the helper has a pair door for the rename requirement and the enum has that member. `shutil`'s copy, move and tree operations are python-level sequences of single-path steps; the spy module spells the same steps in CPython's order, each step one single-path helper call, and never a pair table of its own. The enum is closed and its member list belongs to the code: this plan carries no count, and R1 reads it with `Enum.GetValues`.
  3. *Python succeeds where .NET refuses* is a class, not one overload. Its measured members are three `os.rename` cells (base table): POSIX `rename(2)` replaces an existing file or an empty directory, and `File.Move` / `Directory.Move` refuse. None is a table arm, since there is no exception to classify. The pair door therefore PERFORMS the rename — every entry point R2 attributes to the rename requirement calls it and no longer calls `File.Move` or `Directory.Move` itself — and makes python's successes succeed with the calls each target has. Spy-generated C# compiles for net10.0 and netstandard2.1 with no conditional, and `File.Move(string, string, bool)` is not in netstandard2.1, so a target-specific call sits in Core under `#if NET10_0_OR_GREATER` with a netstandard arm (that target's build is the catcher); a directory destination has no overwrite form on either target, so the door removes the empty destination first. Stated limit: that sequence is not atomic where `rename(2)` is; atomicity is not an outcome class and G1 does not see it. G1's rule makes every member of the class red while a raise remains, the ones not listed here included.
  4. *D1 reserves no name.* The requirement enum and the stamp that ties a door to its requirement are internal to Core; the public face is one static class with one door per requirement for *check* and one for *translate*, plus the pair door. A public Core enum is a bare builtin in every program and reserves its spelling, and a public static class does neither (both measured, Current State); spy sources reach the class by `from sharpy import`. R0–R2 read the enum and the stamps by reflection (`Sharpy.Stdlib.Tests` already sees Core's internals). Chosen over asking the owner for a second reserved name: nothing needs the enum in user programs.
