# P77 — N3: values ready before use

## Context

Rule N3 (`docs/design/name-resolution.md`): every non-constant module-level and `@static` value is initialized before its first read on every path; initializers run top to bottom, after imports and before `main`; a cycle is a compile error where visible, a run-time error otherwise; a throwing initializer is retried; a CLR default is never observed. Issues: #2422 (tracker), #2412 (a const cycle through an alias), #2420 (a call through a module function-typed variable).

## Design Decisions

D3–D5 leave the charter's emission (§3.20k) where a measured cell requires it (owner: "Yes, author reshapes"); each departure is prototyped in C#, not compiler output, and its cost is A12's.

- **D1 (#2420; Semantic).** Delete `ExecutionOrderAnalyzer.DetectInitializerDependencies`: N3 removes its premise (an undefined initialization order). Predicate: the `CodeGenInfo` of a module-level `VariableDeclaration` does not depend on what its initializer reads.
- **D2 (facts; Rule 2).** `CodeGenInfoComputer` records on `Symbol.CodeGenInfo` (symbol-keyed; no new `SemanticInfo` dictionary), and `SymbolSerializer` round-trips: per value `StaticStorage` ∈ {Const, Guarded, Plain} and a generic-host flag; per module `HasSweep`. Guarded = has an initializer and is no C# `const`: a module variable, a computed `const`, a property default, a `@static` field, in every host. No initializer: Plain, as today (owner: "Out of P77").
- **D3 (runtime; rung 2).** `Sharpy.StaticInit` in Sharpy.Core (C# 9): ONE process-wide re-entrant lock. `Run(ref byte state, string name, Action init)`: re-entry on the initializing thread raises `NameError`; a throw restores Uninitialized and rethrows the ORIGINAL exception. `Load` runs a module's sweep once under the lock; a failure is delivered once (to `Main` or the importer; on a lazy host to the read that started it), then reads retry per value. **Departure:** a type initializer calls `TryLoad`, which never waits for the lock. Predicate: no thread waits for the lock while holding a type-initializer lock (prototype: two threads on two lazy hosts finish; with a waiting `TryLoad` neither does).
- **D4 (declaration shape; CodeGen).** A Guarded value is a backing field, a state byte (Uninitialized, Initializing, Assigned, Ready), `Init_x` and a property of the SAME C# name. **Departure:** a variable's or `@static` field's property returns by reference (`get { if (!Swept.Done) Slow_x(); return ref field; }`), a computed const's `ref readonly`; a property default keeps `get` / `set`. A read, a member store, a mutating call and a `ref` / `out` / `in` operand stay today's C# (by value, a struct member store is CS1612 and a struct call a silent copy). Two arms change: a plain store (`StoreForm` Assign, Walrus; an unpacking leaf) is `x_set(v)`, which marks an Uninitialized value Assigned — reads see it, and the sweep still runs the initializer at its position (python's order, `5 7`); `x op= e` is `x_set(x op e)`. Any other use reads, so it initializes first. Predicates: no user expression is left in a static initializer or constructor (C# `const` aside); an arm is picked by `StaticStorage`, never by a type.
- **D5 (sweep; CodeGen).** **Departure:** ONE `Swept` per module (`static readonly bool Done = StaticInit.TryLoad(…)`), none per class. The sweep runs in SOURCE order (R-JT): each import with `HasSweep`, each Guarded value, each non-generic type's values at the type's position; it stops at the first throw. A read into a type not yet reached initializes that one value; a per-class sweep runs the whole type and raises `NameError` with no cycle (A5's two-type cell; prototype). `Main` first requires its module and rethrows the original exception (owner: "Stop before main"); with no Sharpy entry point a module loads on its first use. A GENERIC host is not swept: its accessor checks its state on every read, per closed type (spec residue).
- **D6 (suspension; CodeGen).** C# keeps no returned reference across `await` or `yield`: under D4, a `ref` operand before an awaited argument is CS8178, and `p.x = await f()` compiles and throws `NullReferenceException` (prototype, SDK 10.0.404). In an `async def` or generator body a use other than a plain read or plain store is a statement `Ensure_x()`, then the backing field. Predicate: no accessor's reference is live across a suspension.
- **D7 (operands; Semantic).** `TypeChecker.CheckModifiedArgument` refuses by the operand's resolved symbol (SPY0389; by shape today): a property under `ref` / `out` / `in`, in every host, default or not (owner: "Refuse all at checker"); a `const` under `ref` / `out` (`parameter_modifiers.md`: the caller passes a variable). A variable under any modifier and a computed `const` under `in` run. Predicate: no operand the rule admits is a C# error after D4.
- **D8 (cycles; Validation).** One graph after type checking, at Order 251, replacing `StaticInitializerOrderValidator` and `TypeChecker.DetectConstantCycles`. Nodes: each Guarded value and each `const` with an initializer. Edges: reads resolved through the checker's bound symbols, never the spelling. Between two `const`s, every lexical read (today's SPY0278 set, pinned by its tests). Any other edge is a read in a slot the generator classifies `Always` (owner: "Generated roster"): the validator's map is total over the `Expression` subclasses and `BinaryOperator`, and a test asserts it equal to the generator's. A read in a `Conditionally` slot, a pattern or a nested function body is no edge; a cycle the graph misses is D3's `NameError`. A node on a cycle is SPY0278 (its text says "value" for a non-const). Predicate: a non-const cycle refused at compile time raises on every run.
- **D9 (retirement; R-KD).** SPY0618 retires in D8's commit, with a retirement note; `StaticInitializerOrderMatrixTests` flips by direction: forward cells run, self reads are SPY0278.
- **D10 (interop; rung 3).** A module variable becomes a by-reference C# property: a C# consumer uses it as before, its address too. Generated members carry `[CompilerGenerated]` and discovery skips them; for a module imported by reference it reads `StaticStorage` from the member's CLR shape and `HasSweep` from the load entry, found by a Sharpy.Core attribute (never by name) and required by the importer's sweep at the import's position.
- **Out of contract:** a later module VARIABLE's visibility (SPY0200; N1, #2423; the spec example spells a `const` until P78: owner, "Re-cite to #2423"); #2151's store arm (P79); a module variable declared twice (#2125, R-CY, P21b); a struct behind a PROPERTY (#2268). **Open, the owner's:** `in` on a literal `const` (SPY0908 CS8156 today): drop the keyword, or refuse; the generator excludes the pair with its program.
