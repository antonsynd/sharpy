# P77 — N3: values ready before use

## Context

Rule N3 (`docs/design/name-resolution.md`): every non-constant module-level and `@static` value is initialized before its first read on every path; initializers run top to bottom, after the module's imports and before `main`; a cycle is a compile error where visible, a run-time error otherwise; a throwing initializer is retried; a CLR default is never observed. Issues: #2422 (tracker), #2412 (a const cycle through an alias is not SPY0278), #2420 (a call through a module function-typed variable is SPY0908 CS0103).

## Design Decisions

- **D1 (#2420; Semantic).** Delete `ExecutionOrderAnalyzer.DetectInitializerDependencies`: its premise ("static field initialization order is undefined") is what N3 removes. Predicate: the `CodeGenInfo` of a module-level `VariableDeclaration` does not depend on what its initializer reads. No emitter arm changes.
- **D2 (facts; Rule 2).** `CodeGenInfoComputer` records on `Symbol.CodeGenInfo`, symbol-keyed, no new `SemanticInfo` dictionary: per value `StaticStorage` ∈ {Const, Guarded, Plain}; per module and type `HasSweep` (a Guarded value, a type with one, or an import of a module with one). Guarded = has an initializer and is not a C# `const`: a module variable (a literal one too), a computed `const`, a module or `@static` property default, a `@static` field, on every host kind. A declaration with no initializer stays Plain and prints its CLR default, as today (owner: "Out of P77"). `SymbolSerializer` round-trips both.
- **D3 (runtime; rung 2).** `Sharpy.StaticInit` in Sharpy.Core (C# 9): `Run(ref byte state, string name, Action init)` under ONE process-wide re-entrant lock (no lock order between hosts); re-entry on the initializing thread raises `NameError` (python's type on every generated cycle twin); a throw restores Uninitialized and rethrows the ORIGINAL exception.
- **D4 (declaration shape; CodeGen).** A Guarded value is emitted as a private backing field, a private state byte, `Init_x` (calls D3) and a property of the SAME C# name, so every read, store and `+=` site stays valid C#: `get { if (!Swept.Done && Volatile.Read(ref state) < Assigned) Init_x(); return field; }`. States: Uninitialized, Initializing, Assigned, Ready. A store before readiness sets Assigned: reads see the stored value, and the sweep still runs the initializer at its source position (python's order). Predicate: no user expression remains in a static field initializer, an auto-property initializer or a static constructor of an emitted type (C# `const` aside), so no user exception is wrapped and compiler-owned statics (`@lru_cache`) are ready first.
- **D5 (sweep; CodeGen).** Each host with `HasSweep` gets a nested `Swept` (`static readonly bool Done = RunSweep()`, plus the captured failure). `RunSweep` runs in SOURCE order (R-JT first half): each import whose module has `HasSweep`, each Guarded value, each declared type's `Swept` at the type's position; it catches, records and returns false. The emitted `Main` first requires its module's `Swept` and rethrows the original exception: the program stops before `main`, as python does (owner: "Stop before main"), so a retry is observable only on a lazy host. With no Sharpy entry point a host sweeps on the first read. A generic type sweeps per closed type on first use (spec residue).
- **D6 (`ref` / `out` / `in` operand).** The one consumer that needs a storage location. Each non-const Guarded value also gets a ref-returning accessor (ensure ready, `return ref` field), which the argument arm emits when the operand's `StaticStorage` is Guarded. An instance property is out (ledger).
- **D7 (cycles; Validation).** One graph after type checking, replacing `StaticInitializerOrderValidator` (Order 251) and `TypeChecker.DetectConstantCycles`. Nodes: every Guarded value and every `const` with an initializer in the module. Edges: reads resolved through the checker's bound symbols, never the spelling (alias, class-scope alias, nested path, qualified). A `const` reader keeps today's edge set (every lexical read, lambda bodies included; pinned by SPY0278's tests). Any other reader contributes only UNCONDITIONALLY evaluated reads: no lambda body, no deferred part of a generator, no conditional-expression branch, no right side of `and` / `or` / `??`. Every node on a cycle is SPY0278; a cycle the graph does not hold is D3's `NameError`. Predicate: a non-const cycle refused at compile time would raise on every run.
- **D8 (retirement; R-KD).** SPY0618 and its validator retire in the commit that lands D7, after D4–D5; `DiagnosticCodes` and `DiagnosticExplanations` keep a retirement note. `StaticInitializerOrderMatrixTests` flips by direction (forward cells to the initialized value, self reads to SPY0278) because R-JT's refusal is superseded, not to make a test pass.
- **D9 (interop).** A module variable becomes a C# property. Generated members carry `[CompilerGenerated]` and discovery skips them (rung 3, CLR identity): a module imported by reference exports the names its source declares.
- **Out of contract:** the visibility of a later module VARIABLE (SPY0200; N1, #2423): the 8 rows that cited #2422 for it cite #2423 since 0d3bb5083, and N3's spec example spells a `const` until P78 (owner: "Re-cite to #2423"); a declaration with no initializer; #2151's store arm (P79).
