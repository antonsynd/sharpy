## Context

The five workflow skills were written Feb–Jun 2026 around a **feature-implementation** model:
plan → build in pipeline order → test → confirm completeness. Since July the repo's actual working
model has become **defect-class remediation**: gap-discovery contracts and ratcheted allowlists
(`docs/design/gap-discovery-contracts.md`), the SPY0908 policy (`docs/design/spy0908-policy.md`),
per-batch class cures with owner rulings, mutation-tested guards, and execution-evidence close-outs.

That model is written down in three places — `CLAUDE.md › Testing › Gap-discovery sweeps`,
`docs/design/`, and "Round mechanics (process guardrails, from this repo's own memory)" of every
round plan since 2026-08-13 (§4 of `plan-remediation-round-2026-08-13.md`, §5 of the 08-18 and 08-22 plans) [CORRECTED: section number differs per plan] — **but in none of the five skills**. Each round re-derives the
guardrails by hand inside the plan because the skills that drive the round don't carry them. The
concrete cost shows in the verify rounds recorded in memory: a batch landed with 10 red tests and a
broken regen the implementer never ran; a "fix" and its harness were both vacuous; a fix leaked and
regressed enum args; a full-suite log was a stale-binary false green. Every one of those is a
failure mode the skills could have caught mechanically and none of them currently instruct for.

Two independent observations frame every recommendation below:

1. **Every auditor in the skills is confirmatory.** `verify-plan` checks that referenced files
   exist and conventions hold; `verify-implementation`'s four agents check that the code "matches
   what the plan describes". Nothing is briefed to *refute*: no control run, no mutation of a new
   guard, no probe of cells outside the issue's repro list, no by-direction check on a refusal.
2. **Nothing asks "what class is this a member of?"** `create-plan`'s only root-cause language is
   one bullet ("Root-cause fixes, not patches/bandaids"). `verify-plan` can stamp PASS on a plan
   that patches one arm of a mirrored structure. `compiler-audit` measures file sizes and TODO
   hygiene but never re-measures the allowlist census that `spy0908-policy.md` established.

## Design Decisions

### D1 — One shared verification contract, referenced from every skill

Do not paste the same eight rules into five SKILL.md files; they will drift the way the agent
copies did. Create **`docs/design/verification-contract.md`** and have each skill open with
"Read `docs/design/verification-contract.md` before proceeding; every audit below applies it."
`CLAUDE.md` gets one Critical Rule pointing at it. Contents (each item already exists as a memory
lesson or a round-plan §5 bullet; this just gives them a home the skills can cite):

1. **Class before cell.** A bug is closed by enforcing its class contract, not by patching its
   cell. Name the violated contract; enumerate the cell matrix (position × operand form, callee
   kind × usage form, route table × entry point …); an issue's repro list is a *symptom report,
   not a test plan* — measure more cells than the issue names, and when the spellings you vary
   all agree, change axis. The recurring meta-classes and their standard cures are the table in
   the round plan (SPY0908-as-net → semantic refusal or materialized lowering; silent wrong
   behavior → fix first + sweep; qualified/bare divergence → one shared helper + one alias-deref
   point; position missing a shared check → move to the seam + position matrix; warm ≠ cold →
   differential harness; vacuous instrument → fail loudly + mutation-test).
2. **Guards are falsifiable.** Before claiming a test guards a defect: break the guarded thing
   (invert the predicate, revert the production hunk) and confirm the test goes **red**; restore
   via `cp`/patch, never via `git checkout` in a shared tree. Read both counters. If the
   mutation flows through the test's exemption, the guard is inverted — parameterize the one
   falsifiable arm. An absence assertion (grep for 0 hits, "no SPY0908") needs a positive control
   on the same input. A fix whose reversion leaves the new test green is **inert** (usual cause: a
   fallback path one call later).
3. **Refusals verified by direction.** Before/after against the prior commit distinguishes
   "replaces an ICE with a diagnostic" from "restricts working code" (spy0908-policy.md).
   SPY0908 surfaces only under `run`, never `emit`. Probe `b: bool = expr` to split mistyped
   (SPY0220) from untyped (silence); `print(x)` is never a type probe.
4. **Recorded ≠ applied.** When a change records a fact codegen consumes, run the program and
   compare values end-to-end.
5. **Measurements carry their sha.** Report `count @ sha (measured)`; never extrapolate a batch
   close from a mid-batch run. Before attributing a failure, run the **control** — the same suite
   on the tree *without* the change (worktree at the base commit). An instrument must first be
   shown to detect the no-difference case. A failing step invalidates its dependents, not its
   siblings: finish every independent step and label suspect readings.
6. **The commit gate is the whole solution.** `.claude/scripts/dotnet-serialized test --filter
   "Category!=Benchmark"` across all projects, run in the background while doing read-only work;
   a filtered run is the edit loop, never the gate. Blast radius: anything in `Semantic/` or
   `CodeGen/` reaches `Sharpy.Stdlib.Tests`, `Sharpy.Cli.Tests`, the LSP parity sweep
   (`FrontEndParityTests`, `src/Sharpy.Lsp.Tests/Conformance/`), and the three GapDiscovery sweeps
   that CI runs as *separate steps* (`dotnet10.yml:89–115`: `InteropConformance` #1034,
   `MetamorphicCorpus` #1157, `DifferentialExecution` #1202 — the main Compiler step *excludes* them
   by `FullyQualifiedName!~…`, so a local `Category!=Benchmark` run is the only thing that covers all
   three at once). [CORRECTED: named the concrete harnesses]
7. **Regenerate early; read the diff as findings.** Spy-stdlib C#, spy-test C#, stdlib docs,
   oracle ledger — regenerate at the start of any codegen-touching round, not as a pre-push chore.
   A newly red regenerated test is a live regression until disproven.
8. **Closed ≠ finished.** Completion is derived from issue state plus the plan's own acceptance
   bullets and "Issues to Close", never from "code landed". Closes cite execution evidence at a
   named sha. Every allowlist entry a fix drains is deleted in the same commit; no entry is ever
   added without an issue reference. Spec/doc examples are executed before commit, with outputs
   that *discriminate*. Two tells: a new file with no callers; a promised spec section that greps
   to nothing.
9. **Shared-tree contract for agents (verbatim block).** *The working tree is shared. Never run
   `git checkout`, `git restore`, `git clean`, `git stash`, `git reset`, or `rm` on repo paths.
   REPORT `git status`; do not "make it clean". Stage with explicit per-file pathspecs; check
   `git diff --cached --stat` before committing. Never `git add -A`/`.`.* The lead commits its
   own work in small slices and re-checks `git diff --stat` after each agent wave; when the tree
   is dirty with a peer's work, verify in a `git worktree` at HEAD.

### D2 — Auditors are briefed to refute, not confirm

Every audit prompt in `verify-plan`, `verify-implementation`, and `compiler-audit` changes stance
from "verify X matches" to "find the input that shows X is wrong; report NOT REFUTED only after
naming what you tried". The four `verify-implementation` agents are re-briefed (Phase 4).

### D3 — Plans carry a Defect Class section; verify-plan grades adequacy, not just accuracy

A bug-fix plan without a class, a matrix, and a falsifiable guard per phase is **NEEDS
REVISION**, however accurate its file paths are. The stamp gains an adequacy field so
`implement-plan` can refuse cell-only plans for bug fixes.

### D4 — Delete counts from agentic files; one agent roster

`.claude/agents/*.md` is the only roster (the Copilot copies under `.github/agents/` were removed
2026-08-26 — Claude Code is the sole consumer). Counts ("5 partials", "~4,640 lines") rot and
contradict each other across files; delete them, same principle as the rules-only CLAUDE.md.

### D5 — Verification agents run on a model that can reason adversarially

`verification-expert` (haiku) and `net-axiom-guardian` (haiku) are fine for "run this filter and
report counts"; the refutation briefs in Phase 4 are not. Either raise the definition's `model`
or pass `model` explicitly at spawn time for the adversarial roles, and say which in the skill.
