## Design Decisions

1. **One switch-arm scanner, test-side** (`SwitchArmScan`, in
   `src/Sharpy.Compiler.Tests/Infrastructure/`): parses the production source with Roslyn
   (`Microsoft.CodeAnalysis.CSharp` 5.9.0 flows transitively from Sharpy.Compiler) and returns,
   for a (repo-relative file, method name): the set of **type names** matched by `case` patterns
   across every switch statement *and switch expression* in that method (declaration patterns,
   type patterns, recursive patterns), plus a raw normalized **arm-pattern text** list for
   tuple-pattern switches (`AugmentedCollectionAssignment.Classify`). Repo root located by
   walking up from `AppContext.BaseDirectory` (same pattern as
   `SemanticInfoMergeConformanceTests.FindSemanticInfoSource`). This makes the vacuous pattern
   unwritable: a roster test that consumes the scanner cannot ignore the switch.
2. **Rosters stay, but become cross-checked documentation.** Each totality test asserts
   (a) scanner arms == the roster that claims to mirror them (non-empty positive control first),
   and (b) roster union == reflection universe. Where the switch and the roster already disagree
   (the `DeferStatement` tell), **the switch is the truth** — reclassify the roster in the same
   commit and say so in the commit body; never loosen the assertion to make them agree.
3. **`SourceGlob` is the enumeration seam; `CrashBundleWriter.IsNonSourceSegment` stays the
   predicate authority** (it is `internal` at `CrashBundleWriter.cs:83` [CORRECTED: internal, not public — visible to every migration target via `InternalsVisibleTo`, incl. `sharpyc` = Sharpy.Cli's assembly name; referenced by ~17 test files], so `SourceGlob` can stay internal too; moving it buys nothing).
   Three faces: `EnumerateSourceFiles(baseDir, pattern, option)` (predicate-filtered),
   `ResolveGlob(baseDir, include, exclude?)` (Matcher wrap, predicate-filtered — subsumes
   `ProjectConfig.ResolveGlobPattern`), `EnumerateArtifacts(dir, pattern)` (predicate-FREE — dll,
   json.gz, native; these legitimately enumerate under `bin/`). A predicate-free face is what
   makes a **total** raw-call ban possible in production projects; without it the dll sites would
   force allowlist holes that rot.
4. **Scope split for the scan:** production projects (`Sharpy.Compiler`, `Sharpy.Cli`,
   `Sharpy.Lsp`, `Sharpy.TestInfrastructure`, `Sharpy.Compiler.Benchmarks`) get a zero-raw-call
   scan outside `SourceGlob.cs`; test projects keep the #1660 predicate rule (test bodies
   enumerate their own temp dirs — banning that is noise, and the existing inline
   `IsNonSourceSegment` usage there is correct). `Sharpy.Stdlib`/`Sharpy.Core` are excluded with a
   written justification in the test: their `Directory` calls implement Python-facing runtime
   semantics (`glob`, `os`, `shutil`, `tarfile`), not compiler input discovery.
5. **#1689 cells live in Stdlib.Tests fixtures** (`ndarray_slicing` precedent) because numpy
   cannot run in Compiler.Tests FBIT. They are the NdArray extension of the #1226 evaluation-count
   family and say so in the fixture header.
6. **#1697 fix is property-complete, not literally `Children`-driven:** the token collector's
   statement dispatch handles bodies via `CollectStatementList`; blindly walking `GetChildNodes()`
   would double-visit. The fix collects `item.Target` beside `item.ContextExpression` — the same
   node set `Children` yields for the item — and the deliberate identifier-only readers get a
   one-line justification comment citing #1697 so the next audit doesn't re-flag them.
7. **Mutation discipline (every phase):** production-code mutations run in a git worktree under
   `sharpy.worktrees/` (never the shared tree), restores via `cp` from a pre-mutation copy, never
   git; clear mutated fixture `bin/` afterwards (compiler-identity cache poison). Every commit
   that adds a guard records `broken → red (N failed) / restored → green (N passed) @ sha` in its
   body. An absence assertion ships only with its positive control.
