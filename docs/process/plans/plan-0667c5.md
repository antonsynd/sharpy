## Defect Class

- **Violated contracts (one per batch):**
  1. *Exit model (Batch 4):* codegen and every analysis share ONE model of how a `with`/`finally`/`defer` body can exit — protocol shape {1-param `__exit__`/IDisposable (never suppresses), `self`+3 (may suppress — "3-arg" and "4-arg" are ONE shape, named **suppression-capable** once)} × body exit {return, raise, break, continue, fall-through, `?` early-return, yield}; where C# cannot express the exit, Sharpy refuses by name before codegen; where the successor is reachable, reachability, definite assignment and the emitter agree that it is.
  2. *Unpacking (Batch 5a):* tuple-unpacking positions {assignment, for statement, comprehension for-clause, with-as} share ONE target grammar (list display ≡ tuple), ONE arity rule (a star absorbs ≥ 0 elements) and ONE binder/lowering, over source kinds {tuple type, `list[T]`} and target shapes {flat, nested, starred first/middle/last}.
  3. *Hoist sink (Batch 5b):* lowering never changes evaluation cardinality, conditionality, timing, order, or scope — a hoisted lowering has exactly one legal sink (a statement position that dominates the expression, in the same scope, evaluated exactly when the expression is), and the emitter MANUFACTURES that sink when none exists; earlier operands are captured so left-to-right order survives; a walrus binds where it is evaluated and Sharpy's own DA refuses the read that C# would refuse.

## Design Decisions

1. **The exit shape is a materialized semantic fact, not an emitter inspection (Rule 2).** `ContextManagerKind` stays; a second axis `ContextManagerExitShape { Simple, SuppressionCapable }` is decided in `CheckWith` (from the resolved `__exit__`/`__aexit__` symbol's parameter count — the same resolution `GetDunderEnterReturnType` already performs for `__enter__`) and recorded with the kind as one node-keyed record `ContextManagerLowering(Kind, ExitShape, ExitMethod)` on the context expression (replacing the bare `ContextManagerKind` dictionary at `SemanticInfo.cs:278`, which is ALREADY in `MergeFrom` :1828 — the replacement keeps that line; the `MergeFrom` class guard from Batch 0 watches it). `IrWithItem` carries `ExitShape` and the resolved `ExitMethod` symbol (symbol-keyed carrier, pattern (a)); the emitter reads the IR and nothing else — `TryGetExitMethod`/`ExtractTypeSymbolForContextManager` are deleted. IDisposable/IAsyncDisposable are `Simple`. Name the shape ONCE: "suppression-capable" in code, diagnostics and spec (`context_managers.md` renames "3-arg form" to "the suppression-capable form (`self` plus three parameters)").
2. **Reachability consumes the fact through ONE CFG factory (R-M).** `BuildWith` adds, for every item whose shape is `SuppressionCapable`, an exception edge from the with-body block to the `with_exit` block (`ConnectException`, so DA's must-assign treats it conservatively — the same mechanism `BuildTry` uses for handlers) — the successor is reachable even when the body always exits; `Simple` managers are unchanged. `ControlFlowGraphCache` takes the `SemanticInfo` at construction and passes it to EVERY builder (`GetOrBuild` included); `ValidationContext` constructs it once. SPY0266 gains a steer when a missing-return block's predecessor is a `with_exit` of a suppression-capable manager: "the `with` body can fall through when `__exit__` suppresses — add a `return`/`raise` after the `with`, or use a 1-parameter `__exit__`". `-> None` functions and generators stay clean (b4_11, existing :113 skip). Fabricated fall-through is rejected (R-M).
3. **Refusals by name, at the TypeChecker's control-flow seam, one walker.** `CheckDeferBodyControlFlow` (SPY0333) is generalized to `ReportEscapingControlTransfer(body, host, code)`: return/yield always escape; break/continue escape unless a loop declared inside the body encloses them; nested def/lambda bodies are not traversed. Finally bodies call it with **SPY0702 `FinallyControlTransfer`** for return/break/continue only (yield keeps SPY0272 — one diagnostic per transfer; the generator cell is the positive control against double reporting). `yield` inside a suppression-capable `with` → **SPY0703 `YieldInSuppressingWith`** in `GeneratorValidator` beside SPY0272 (`FindYieldInSuppressingWith`: any `WithStatement` whose items include a suppression-capable manager and whose body contains a `YieldStatement` at any depth short of a nested def), with R-N's steer; `Simple` managers keep yielding (b4_10). Both codes are Validation-overflow errors with `DiagnosticExplanations` entries; the driven-iterator lowering stays parked (recorded in #1745).
4. **List-display targets normalize at the one seam (R-J).** `CanonicalizeStoreTarget`'s `ListLiteral` arm returns a `TupleLiteral` with `IsListDisplay = true` (immutable-AST init property, used only by `UnparseVisitor` to print `[a, b]` back and by the augmented-assignment refusal to say "list display"); the universe stays five kinds; the two defensive arms and the totality test's justification are deleted; `ParseStoreTarget` already routes for/comprehension/with through the seam. Augmented assignment onto a tuple/list display is refused with one message naming the display kind (python: SyntaxError for both).
5. **One unpacking rule, one binder, one lowering (Batch 5a).** A checker helper `BindUnpackingTargets(targets, sourceType, position)` replaces the four inline formulas: arity with a star is "≥ targets − 1" (exact otherwise), element types come from the tuple's positions or from `list[T]`'s `T` (the star binds `list[T]`, or a tuple of the rest types collapsed by the existing `CheckStarUnpacking` rule), nested targets recurse, symbols are defined through `DefineForLoopTupleTargets` extended with a `StarExpression` arm; ONE SPY0239 wording with the position as a suffix. The emitter's `GenerateStarUnpacking` becomes the shared typed-temp lowering for all four routes (`foreach (var __e in xs) { <star unpack of __e> … }`); this typed-temp helper is the one 5b's sink stack reuses for unpacking temps (P12).
