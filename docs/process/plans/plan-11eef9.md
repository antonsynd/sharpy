# P75 — static initializers run in source order (CodeGen member layout + the forward-read refusal)

## Context

A type's `@static` field, `const` (emitted `static readonly` when its initializer is not a compile-time constant) and `@static` property default are C# **static initializers**, and C# runs them in the **textual order of the generated C#**. `RoslynEmitter.GenerateClassMembers` lays a type out as `[fields][methods + nested types in source order][property groups][event groups][synthesized members]`, so a `@static` field or `const` initializer that reads an **earlier** `@static` property observes the property's backing field before its initializer ran and the program prints `0` silently (#2396, lane silent-wrong · reach program). P21h could not fix the layout (it lands alone — snapshot churn), so it refused the BARE spelling with a temporary SPY0200 arm citing #2396 (`TypeChecker.ClassScopeRule.cs:437-447`, `IsStaticInitializationOrderRead`) and documented the exception in `docs/language_specification/variable_scoping.md:382-388`; the QUALIFIED spelling (`Host.sp`) runs `0` today. The P21h F1 order rule exempts every `const` sibling from its forward-read refusal, so a forward read of a `const` that is NOT a compile-time constant (a `static readonly`) also runs `0` (the #2396 comment cell, `0 7`).

Charter: `.claude/plans/remediation-round-2026-09-20-batching.md` §3.20g (row 6c⁶′); rulings R-JT (layout + forward refusal, D2 a) and R-JU (placement, D3 a) at https://github.com/antonsynd/sharpy/issues/2396#issuecomment-6511445507. Issue: https://github.com/antonsynd/sharpy/issues/2396.
