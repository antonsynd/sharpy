## Design Decisions

1. **The fact is semantic and symbol-keyed.** Move `IsModuleConstCompileTime` / `ComputeModuleConstIsCompileTime` / `ConstEligiblePrimitive` / `ResolvesToCompileTimeConst` / `LowersToConstantExpression` out of `CodeGenInfoComputer` into `Semantic/ConstEligibility.cs` (a `TypeChecker`-owned analysis). It runs at the end of the module pass, BEFORE `_validationPipeline.Validate` (`TypeChecker.cs:~600`), over every `VariableDeclaration { IsConst: true }` the module contains (module body, class/struct bodies, function bodies, nested blocks — collected by one `AstHelper.ContainsDescendant`-style walk, not a hand roster), resolving each symbol's fact lazily with a per-scope declaration index (module and type bodies allow forward references, as C# does; locals resolve in order — a forward reference to a later local const is `false`, which is also what the checker already refuses). The result is stored on `SemanticBinding.SetCompileTimeConstant(VariableSymbol, bool)` (symbol-keyed, like `SetVariableType`). `CodeGenInfoComputer.ProcessModuleLevelConstant`, `ProcessField` and `LocalNameAllocator` (`:155`) copy it into `CodeGenInfo.IsCompileTimeConstant` — the emitter reads ONLY `CodeGenInfo` (Rule 2 pattern (a)).
