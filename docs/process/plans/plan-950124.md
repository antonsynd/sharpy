## Design Decisions

1. **The inventory scans by scrutinee TYPE at compilation level, over two roots: AST `Node` and lowering `IrNode`.** A Roslyn `CSharpCompilation` is built from each project's sources plus (a) a synthesized `global using` tree for the SDK implicit-usings set and any `<Using Include=…>` items read from the `.csproj`, and (b) metadata references gathered from the test process's **trusted-platform-assembly list** (`AppContext.GetData("TRUSTED_PLATFORM_ASSEMBLIES")`, split on the path separator) [CORRECTED: was "gathered from the test AppDomain" — `AppDomain.CurrentDomain.GetAssemblies()` (the `AttributeAbsenceVerdictScopeTests` precedent, `Discovery/AttributeAbsenceVerdictScopeTests.cs:47–50`) returns only assemblies already *loaded*; nothing in `Sharpy.Compiler.Tests` touches an OmniSharp type, so the LSP root's `MediatR`/`OmniSharp.Extensions.*` references would be absent and `unresolved > 0` would fire for a reason unrelated to aliases or usings. The TPA list names every assembly the deps.json resolved, loaded or not, and is equally hermetic], with `Sharpy.Core` given the `SharpyRT` alias read from the `.csproj` `<Aliases>` element (both projects also alias `Sharpy.Stdlib` as `SharpyStdlib` — read every `<Aliases>`, not just the one) — never `obj/` artifacts and never `bin/` probing (hermetic instrument; the 42-unresolved finding is the reason). Every switch scrutinee in every file is classified {AST-typed, IrNode-typed, other, **unresolved**}; `unresolved > 0` fails the inventory (fail-loud), because an unresolved scrutinee is exactly where a dispatch hides. Rationale: verification-contract §1 "instruments that pass vacuously"; the issue body's point 3 (a syntax parse cannot do this). `IrNode` joins the root set so the four `RewriteNode` rows keep their `documented-by-design` justification instead of silently leaving the inventory; `CodeValidator.ValidateNode` (Roslyn `SyntaxNode`) leaves it as a fossil.
2. **One inventory, one roster, both projects — housed in `Sharpy.Compiler.Tests`.** `Sharpy.Compiler.Tests.csproj` gains `<ProjectReference Include="../Sharpy.Lsp/Sharpy.Lsp.csproj" />` so the LSP's references (OmniSharp) are in the AppDomain and the LSP root compiles with the same reference-gathering seam as the compiler root; LSP rows are keyed `Sharpy.Lsp/<path>::Type.Method` (no compiler path starts with `Sharpy.Lsp/`, and the 75 existing keys do not churn). Precedent: `WrapperNodeUnwrapConformanceTests` already scans LSP sources from the compiler test project. LSP *source-scan* totality guards live under `src/Sharpy.Compiler.Tests/Lsp/` (they need `SwitchArmScan` and the compiler's reflection universe, not the LSP assembly); LSP *behavioral* cells (a kind found without hover/tokens) live in `Sharpy.Lsp.Tests` and are cited as `refusal-net:<class>` — the citation check resolves such classes by source scan of `src/Sharpy.Lsp.Tests` when the site is an LSP site. Rejected: moving `SwitchArmScan` into `Sharpy.TestInfrastructure` and splitting the roster across two test projects — two rosters with one rule set is the mirrored-site shape this whole lineage exists to kill.
3. **Justification categories are unchanged** (`guarded-by`, `documented-by-design`, `walker-default-contract`, `refusal-net`, `pending-guard`), per the charter's "roster under existing justification categories". A `pending-guard` row may cite only an OPEN issue; when this plan closes #1716 the harness's category positive-control must not require a `pending-guard` row to exist (today it does — `EveryJustificationCategory_HasAtLeastOneSite` lists it as required; Phase 3 relaxes exactly that category to "allowed, not required", with the format check kept).
4. **Rosters derive from the switch; universes derive from reflection; families share one universe.** Each family guard states its universe once (e.g. assignment-target kinds = the arms of `TypeChecker.IsValidAssignmentTarget`, which the parser's target grammar is asserted against; declaration kinds = concrete `Statement` types that declare a type), pins every member site's arm set with `SwitchArmScan`, and requires a reason string for any site whose arms are a strict subset. A new kind therefore fails every family member at once rather than one guard somewhere. (#1694/#1709 Design Decision 4, generalized.)

This is the minimal cure that Batch 5 (#1680, inline walrus emission everywhere) can later subsume; the fixtures outlive that change. Rule 2 unaffected: the helper is a pure AST predicate consumed by the emitter as today.
