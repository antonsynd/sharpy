# P22h — continuation lines & the close-line quote rule (#2279 #2280)

## Context

(charter `.claude/plans/remediation-round-2026-09-20-batching.md` §3.1b; rulings R-FU, R-FV, R-GC of 2026-10-08):

- **#2279** (R-FU, FIRST; `lane:silent-wrong` · `reach:program`; class tracker) — lines the indent map reads as
  **continuations** escape the indent-only check's block-depth judgment. Seam 1: an open `(`/`[`/`{` is followed to the
  end of the source, so every later line is a bracket continuation; the full and range fallbacks re-indent continuation
  lines to the bracket's block level and the check never judges them — `xs = [1,` above a block moves `print(y)` out of
  its `if`; `@[foo` moves both `pass` lines to column 0; `if foo("abc):` / ``if foo(`x):`` have the `)` inside text the
  lexer reads as a string or a backtick name, so the bracket is open at the line's END to every lexer fact and the body
  line is "the user's continuation". Seam 2: the line after an error recovery is read as a continuation (recovery emits
  no `Newline`); P22g made it depth-judged (no wrong edit) but it is never a repair target (`x = $` then `      y = 1`:
  on-type and Format Document apply nothing).
- **#2280** (R-FV; `lane:tooling` · `reach:program`; class tracker) — arm (b) of `RePairedCloser` (R-FR) reads "the text
  the lexer gives up on the close line of a re-paired run holds a quote character"; the span starts at the aborted
  literal's own opener (`UnreadTextStart(fromTheAbortedLiteral: true)`), so the aborted literal's OWN delimiter counts as
  an orphan. A closer line ending in a short string or f-string that aborts inside itself lost nothing, sets the fact,
  and every route loses the repair the document needs (24 cells, 0 wrong edits).

## Design Decisions

1. **One lexer fact for "a bracket the lexer never saw closed" (R-FU, lexer-internal, no carrier).** `Lexer` gains
   `internal int? BracketLeftOpenAtLine` — the 1-based line of the OPENER of the outermost bracket the lexer left open,
   recorded at the FIRST of: (i) the end of the source with `_bracketDepth > 0` (`NextToken`'s EOF arm); (ii) a recovery
   whose dropped line's END has a bracket open (`DroppedLineContinues`' bracket arm — opened before the abort, in which
   case the opener line is where `_bracketDepth` went 0 → 1, tracked in a new `_outermostBracketLine` beside `:1171`; or
   opened in the given-up text, in which case it is the dropped line itself). The first event is the minimal line (a
   later bracket opens later; recovery resets depth). `DroppedLineContinues` returns a small `LineEnd` (bracket open ·
   trailing backslash) so `RecoverFromError` can tell the arms; `RecoveryResumesAfterAContinuedLine` keeps both (the
   backslash arm's behaviour is untouched). Doc comment: a bracket closed inside an unterminated string or backtick name
   is open to the lexer — the user's intent is a parser-level guess R-FU rejected. Rejected: computing it in the map from
   tokens (cannot see the abandoned case); a diagnostic (an open bracket at EOF is the parser's SPY0104; the editor fact
   is not a user-facing error).
2. **The map freezes every line below the opener; the check enforces it (R-FU: "no edits below the opener's line").**
   `BuildIndentMap` returns `OpenBracketLine` (the lexer's fact, 1-based, null when none). Builders: `ReindentDocument`
   returns lines `> OpenBracketLine` verbatim (whitespace-only lines included); `ComputeIndentOnlyRangeEdits` skips them;
   the on-type handler refuses a request on one. Check: clause 7 of `IndentOnlyPreserved` — every line strictly below
   `before.OpenBracketLine` is byte-identical in the applied text. Lines at or above the opener keep every repair (A1b);
   the opener line itself is a logical start judged by clauses 4 and 6 as today. Consequence by direction: a repair of a
   misindented line below an abandoned bracket (A3 `  w = 3`, A5 `return 1`, the `a)` continuation rows) is no longer
   applied — the ruling's words; a future (b) can stack a content rule for the line typed inside a genuinely open bracket.
3. **The recovery line is a logical-line start (R-FU: "the recovery line becomes a repair target").** In
   `BuildIndentMap`'s token walk, `atLogicalLineStart` is reset at every `RecoveryResumes` point NOT in
   `RecoveryResumesAfterAContinuedLine` (the backslash-continued resume stays a continuation; the bracket-continued one is
   below an opener and frozen anyway). The line then takes the map's width rule like any statement (`opensBlock` of the
   dropped line stays unset — no "ends in a colon" guess for a partially read line; A8 stays refused by clause 6) and is
   judged by clauses 4 and 6 in both maps, so a re-indent that moves it a block (the `WideCloserLineAbort` on-type 1 cell)
   is still refused. `HiddenAfterRecovery` and `DepthJudgedLines` are retired in the same commit (empty by construction);
   the 7-tuple becomes `(…, OpenBracketLine)` — converting it to a named record is allowed if the diff stays mechanical.
   **Clause 6b [CORRECTED: added at /verify-plan 2026-10-09 — see the Adversarial Review's wide-twin bullet]:** an
   EDITED judged line must land on a level of the applied text's width stack (`BlockDepths`: deeper than the stack's top,
   or equal to a width on it); a repaired line whose applied width is on no level (`widths.IndexOf(width) < 0` on a
   multiple-of-4, tab-free width) is refused. Today the comparison exempts every line whose SOURCE depth is −1, so the
   recovery line repaired alone in an 8-space document (W1: `    y = 1` on `[0, 8]`) is accepted while the lexer reads
   the next line one block deeper. The identity twin (`    y = 1` on `[0, 4]`) lands on a level and keeps its repair
   (A6, A6b). Clause 6b judges EDITED lines only — an unchanged misindented line keeps its exemption (A1b's `x = 1` under
   a range-line request elsewhere) — and its direction record lists every hand cell it newly refuses: a refused text
   that carries an SPY0014 at that line is `wrong output` → refused, not `worked` → refused.
4. **Arm (b) reads the quote's role from the given-up text (R-FV (a), lexer-internal).** `NoteUnreadLine` replaces
   `IndexOfAny` with `LeavesAQuoteUnpairedAtLineEnd(span)`: a mode of the scanner's `WalkFrom` (`Mode.CloseLine`) that
   reads the given-up text from its start and returns true iff, at the line's end, a literal is open (short or triple:
   the orphan's closer `'` opens one), OR text the walk cannot pair holds a quote — the remainder after a `#` outside a
   literal (a comment to the lexer, string text to the user: read as TEXT it pairs the two apostrophes of `$  # it's'` and
   loses the stray-closed `cmt` twin; read as a COMMENT it is skipped and loses the same twin — Adversarial Review) and
   the text of an UNTERMINATED backtick name (given up with the line; `` `' ``, `` `x' ``, `` `it's' ``) — judged by
   today's `IndexOfAny` on that remainder [CORRECTED: the `#`-as-text spelling was refuted by the stray-closed `cmt`
   twin, hand model `.claude/tmp/p22h-verify/model_p22h.py`]; a TERMINATED backtick name is opaque; a closed string literal (the aborted literal's own `"\q"`, `f"{x!q}"`,
   `f"}"`) contributes nothing; the own-quote-in-spec fork keeps the scanner's "either walk" rule (so `f"{x:">}"` stays
   set — a pinned limit). Everything else in `WalkFrom` (prefixes, raw escapes, triples, fields, nested literals) is
   shared, so the clean-document differential and the 512 scanner/state theories guard the shared half; the mode is
   exercised by its own hand rows. Rejected: a second hand walk (a third model of the lexer's literal reads to keep in
   step); "both walks" at the spec fork (would repair `f"{x:">}"` but contradicts #2276's rule and opens a missing-fact
   shape `_ = '""" + f"{x:"'"`); R-FV (c). The "orphan still being typed" shapes (`_ = '""" + <tail>`) have no lexer
   signature once the tail's own quotes pair — they are R-FQ's class and are pinned + posted on #2274, with the
   quote-free `$` member measured at be1c16fcf as the proof the class pre-exists.

   #2279; `S6o` (`closeline-own-<tail>`
   no stray, `repair-own-<tail>` the closed orphan `_ = '""" + <tail>'`, tails spelled with `{q}`/`{o}` like
