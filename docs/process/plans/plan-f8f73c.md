# P21e — declaration-position totality (#2063 tracker · #2314 · #2319; #2316 folded)

## Context

A declaration statement — a type definition (`class`, `@dataclass class`, `struct`, `interface`, `union`,
`delegate`, `enum`), a `type` alias, an `import` / `from … import`, or a nested `def` — must have ONE
decided verdict at every position it can be written in. Today the verdict is decided per kind and per
position by whichever pass happens to meet the statement: NameResolver declares the module body and the
type bodies; the TypeChecker refuses six type-definition kinds it meets without a symbol with an
internal-sounding SPY0202 "Class symbol for 'A' not found" (and never meets `enum`, which reaches the
emitter's SPY0510 ICE); an import in a function body binds nothing and the use is SPY0200; an import in a
type body is an SPY0510 ICE; a builtin-named `type` alias is SPY0212 at module level, accepted-and-ignored
or accepted-and-applied in a function (two silent outcomes keyed on the name), and accepted in a class
body; a second nested `def f` in one block is a CS0128 ICE or a misleading SPY0220 depending on which def
the call fits, and a nested-block shadow is CS0136.

Rulings (authoritative, do not re-ask): **R-CS** (#2063 — refuse function-local type definitions and
imports with ONE new Validation code + steer; two-way), **R-HJ** (#2314 — a second `def f` in the SAME
block is SPY0204; sibling blocks are fresh bindings; a nested-block shadow follows B2, "the plan measures
local-function name versioning vs CS0136 — then a Sharpy refusal pre-empts it"), **R-HK** (#2063 — the
group re-scoped to declaration-position totality; P54's `TypeDefinitionOwnSymbolMatrixTests` extended
FIRST; #2316 folded). #2319's acceptance (SPY0212 at every `type` position; `type Fresh = …` in a function
stays legal) is the issue's own, placed by the 2026-10-15 batching comment.

## Design Decisions

**D1 — One validator owns every POSITION verdict: `DeclarationPositionValidator` (Order 53).** A `ValidatingAstWalker` that visits every statement list with an explicit position context — `ModuleBody`, `ModuleBlock`, `TypeBody`, `TypeBodyBlock`, `FunctionBody`, `FunctionBlock` — by overriding the composite visitors (`VisitModule`, `VisitClassDef`/`Struct`/`Interface`/`Union`, `VisitFunctionDef`, `VisitIfStatement` (then/elif/else), `VisitForStatement`/`While` (+ `ElseBody`), `VisitTryStatement` (body, each `ExceptHandler.Body`, else, finally), `VisitWithStatement`, `VisitMatchStatement` (each case body)); property accessor / observer bodies count as function bodies. ONE switch, `ClassifyDeclaration(Statement, Position)`, decides: a type definition (`ClassDef`, `StructDef`, `InterfaceDef`, `UnionDef`, `DelegateDef`, `EnumDef`, through `UnwrapDecorated()` so `@dataclass` is the same arm) at any position other than `ModuleBody`/`TypeBody` → **SPY0708** with the type steer; an `ImportStatement`/`FromImportStatement` at any position other than `ModuleBody` → **SPY0708** with the import steer (R-CS: "import at module level" — a type body is not module level, and probes g/w/x are ICEs today); a `TypeAlias` whose name `BuiltinNameShadowing.Classify(…, isTypeDeclaration: true)` returns `Refused` at a position other than `ModuleBody`/`TypeBody` → **SPY0212** with `BuiltinNameShadowing.RefusalMessage(name)` at the name token (the declaring positions are NameResolver's, D2); a nested `FunctionDef` (positions `FunctionBody`/`FunctionBlock`) whose name was already declared by a def in the same block, or in an enclosing or enclosed block of the same function → **SPY0204** (D5). Everything else falls through untouched (members, module declarations, executable statements — #2148's type-body executable statements are explicitly NOT this validator's). Rung: N/A — a syntactic position rule on the AST; no Core type or CLR surface carries it. Rejected: (C) four arms in the TypeChecker where each symbol-less declaration is met (`ReportUndeclaredTypeDefinition`, `CheckEnum`, the `ImportStatement` no-op arm, `RegisterScopedTypeAlias`, the nested-def `Define`): four files discovering position through four proxies (no symbol / no import binding / alias re-registration / scope collision), the exact parallel-site shape contract §1 names; and the checker's symbol table does not model blocks, so "same block" would be a fifth model. The validator is also where `TypeBodyStatementValidator` (Order 51) already classifies type-body statements; the two stay separate because their contracts differ (what a TYPE BODY admits vs where a DECLARATION may stand) and each carries its own `DispatchSiteInventoryTests` row.

**D2 — SPY0212 has two owners by position, one classifier, one message.** NameResolver's `RefuseBuiltinTypeNameShadowing` gate stays the owner of the DECLARING positions and is applied by BOTH dispatchers — `ResolveDeclaration` (module body, already) and `ResolveNestedTypeDeclaration` (type body, missing: cells u/v/r). The validator (D1) owns the non-declaring positions for the alias kind only (a type definition there is refused by position, and its name is moot: expected set {SPY0708}). The matrix pins exactly one SPY0212 per builtin-named alias cell at all 12 positions, so a gap or a double-report at any position is red. Rejected: moving the alias arm out of the NameResolver gate (its switch is deliberately total over the type-declaring forms, #1241) or into `RegisterScopedTypeAlias` (reached at type-body re-registration too; its early return would hide the type-body hole behind NameResolver's).

**D3 — The TypeChecker stops REPORTING and keeps DECLINING.** `ReportUndeclaredTypeDefinition` becomes a silent skip (`LookupTypeDefinitionSymbol` still returns null and every caller still returns before writing; the doc comment names the validator as the refusal's owner and this plan). `CheckEnum` gains the same own-symbol lookup (`LookupTypeDefinitionSymbol(enumDef, enumDef.Name)`; null → return before checking member values against a scope that is not the enum's). A validator hole would now surface as an emitter SPY0510 ICE (no silence: `GenerateBodyStatements` has no type-definition arm), and the matrix is the guard against the hole. `IsDuplicateTypeDefinition` is deleted with its only caller.

**D4 — `LookupDeclaredType` applies the P54 identity rule.** `SemanticContext.LookupDeclaredType(declaration, name)` returns a symbol only when `!Builtins.IsBuiltinSymbol(symbol) && symbol.IsDeclaredAt(declaration)` [CORRECTED: verify-plan — `SemanticContext.Builtins` is the `BuiltinRegistry`; `SymbolTable` on the context is `IGlobalSymbolTable` and has no `BuiltinRegistry` member] — both for the `NestedTypeIndex` answer and for the by-name fallback (`NestedTypeIndex.SymbolFor` keeps its index; the fallback moves behind the predicate). A declaration that owns no symbol (every non-declaring position) answers null, and all ten validator callers already early-return on null — #2316 cell 3's cascade (SPY0701 with an empty location, SPY0325 against the master `list`) ends at one seam. `NestedTypeIndex.Add`'s walk into function bodies is kept: it only ever indexed definitions that own no symbol (nested types are type-body members), so after this change those entries answer null through the predicate — harmless, and one fewer thing to reason about than a second walk shape.

**D5 — A nested def may not re-declare a name across blocks of one function (R-HJ's measured branch).** Measured @ 03eee7528: the emitter spells every local function `NameCasing.ResolveMethod(name)` with no versioning (`RoslynEmitter.Statements.cs:265`; `LocalNameAllocator` covers locals and parameters only), so a nested-block shadow is CS0136 in BOTH source orders (k, y) — R-HJ: "then a Sharpy refusal pre-empts it". Verdict: SPY0204 "function 'f' is already defined in this scope" at the LATER def in source order when another def of that name exists in the same block, an enclosing block, or an enclosed block of the same function (sibling blocks are fresh bindings — j runs). Door: two-way — extending `LocalNameAllocator`/`CodeGenInfo` to local functions later relaxes this to B2's shadowing without touching the validator's other arms. A def shadowing a local VARIABLE or parameter is outside this axis (z runs today because of the `f`/`F` casing split; a backtick-escaped def would collide — a ledger row for the prober, not a cell here).

**D5b [ADDED: implement-plan, lead ruling 2026-10-23 — NEEDS OWNER CONFIRMATION at the next batching]** — the standalone verifier found that two defs of one name in SIBLING `match` arms are SPY0908 CS0128 at HEAD and after Phase 4: the emitter lowers a `match` to ONE C# `switch` whose sections share a declaration space, and local functions are not versioned (D5); locals in sibling arms run because they are versioned. R-HJ's text says sibling blocks are fresh bindings; its measured branch says a Sharpy refusal pre-empts a C# collision the emitter cannot avoid. Ruled by the lead (ICE → refusal, two-way door): for the nested-def arm, the arms of one `match` are ONE block → SPY0204 at the later def; every other sibling shape (if/elif/else, try/except/else/finally, for/while vs else) stays a fresh binding (measured running). The door that relaxes both this and the nested-block shadow is local-function name versioning (D5's door), recorded on #1974. The generator's nested-def relation axis gains `sibling-else`, `sibling-except` and `match-arms`.

**D6 — A call that fits only the refused second def keeps its SPY0220; a use of a refused import or alias likewise keeps its checker diagnostic.** The first def is the binding (the checker's `Define` guard keeps the first symbol); a call that matches only the refused def is reported against the binding that exists — the same shape as a module-level duplicate (NameResolver refuses the second with SPY0204 and returns before defining; a call fitting only it is SPY0220). Expected sets: same-block × {fits-first, none} → {SPY0204}; same-block × fits-second → {SPY0204 at the def, SPY0220 at the call}. [ADDED: verify-plan — the validator runs after the checker (`TypeChecker.cs:734`), so the same rule covers the other two kinds: a use of a function-local import is still SPY0200 (the import binds nothing), and a use of a refused builtin-named alias is whatever the checker's registration gives today (`type list = int` applied → no use-site error; `type int = str` ignored → SPY0220 at `a: int = "x"`). Decided: the use-site diagnostic is the existing cascade on the same mistake and is NOT suppressed; the matrix's import/alias kinds do not use the binding (oracle (3) compares the rest to the control), and the `.error` fixtures that carry a use pin the cascade line as a second expected substring so a change in it is visible.] #2314's pre-ruling acceptance bullet ("no type error at a call site that only exists because the second def was ignored") is superseded by R-HJ: under refusal the second def IS ignored by ruling, and the cascade names the same mistake. Recorded as the decided verdict; the close-out comment on #2314 says so. [ADDED: implement-plan — measured by the Phase 1 generator: for the NESTED relations the checker binds a call to the lexically nearest def, so the cascade depends on where the call stands. The matrix places each call where the FIRST def is the binding (outer-first: in the outer block after the `if`; inner-first: in the inner block after the inner def), and there HEAD agrees with the D6 rule in all 18 refused cells. With the call in the later def's block the SPY0220 cascade inverts in two cells (outer-first × call inside the inner block; inner-first × call after both defs). The program is refused by SPY0204 either way; the cascade follows the checker's lexical binding and is not changed by this plan.]

**D7 — A fresh-named alias in a block is legal and block-scoped (unchanged).** `type Fresh = str` in an `if` in a def runs (q); in a module `try:` the block itself is ModuleLevelValidator's SPY0340 (e) and the alias draws nothing of its own. Module-block cells therefore carry SPY0340 at the `try` in EVERY kind's expected set — the block's verdict is not this plan's and is pinned as a literal, not derived.

**D8 — Boundary with #2148 (type-body executable statements, §3.22 B6).** This plan refuses the DECLARATION inside a class-body `if` (h → SPY0708); it does not refuse the `if` (TypeBodyStatementValidator's `TODO(#2148)` stays). The expected set for the `TypeBodyBlock` position is {SPY0708} and nothing at the `if`.

**D9 — The emitter is untouched (Rule 2).** The SPY0510 arms (`RoslynEmitter.Statements.cs:227`, `ClassMembers.cs:274/548`) stay as backstops; codegen is skipped on any semantic error, so a refused program never reaches them. No `SemanticInfo`/`CodeGenInfo` fact is added.

**D10 — New code SPY0708 `ValidationOverflow.DeclarationOutsideDeclaringPosition`** ("next free after SPY0708" in R-CS's text was written when SPY0708 was the next free; it still is @ 03eee7528). Messages: `"a {class|struct|interface|union|delegate|enum} cannot be declared inside a function or a block; declare it at module or class level"` and `"an import is not allowed inside a {function|block|class body}; import at module level"`. One `DiagnosticExplanations` entry (guarded by `DiagnosticExplanationsTests`), one `DispatchSiteInventoryTests` row (`refusal-net:TypeDefinitionOwnSymbolMatrixTests`), one `docs/architecture.md` registry line (Order 53), `Validation/README.md` list entry. SPY0204 and SPY0212 reused with their existing wording families.

**D11 — Spec is authoritative; three files gain one sentence + one executed block each (Rule 7, contract §8):** `type_aliases.md` (an error-asserted block `<!-- spec-sweep: error SPY0212 -->` with a builtin name at a function position; the sentence "A `type` alias may not take a builtin type name at any position"); `nested_types.md` or `classes.md` (one sentence: types are declared at module level or in a type body; a type definition or an import in a function body or a block is refused — `<!-- spec-sweep: error SPY0708 -->` block); `function_definition.md` (one sentence: overload sets live at module and type level; a repeated nested `def` in one function is an error; sibling blocks are fresh bindings — `<!-- spec-sweep: error SPY0204 -->` block) with `overload_resolution.md` pointing at it. `import_statements.md` gains the import sentence (its two `#1952` rows are NOT drained here — R-BG's drain-as-you-touch applies to the files whose text this plan changes for its own contract: `type_aliases.md` (0 rows), `function_definition.md` (2), `overload_resolution.md` (4); the import sentence goes in a new paragraph and the file's rows are inspected only: if a row's block is a fragment it gets the marker in the same commit, otherwise it stays).
