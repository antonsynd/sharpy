## Design Decisions

Rung: every fact here is a SOURCE-TEXT fact read by an editor tool; the language ladder (`.spy` / Core C# / CLR bridge /
name-keyed semantic rule) does not apply, but the same "lowest layer that already carries the fact" rule does — the
helper reads the Compiler's existing facts (`LineDiff.Split`, `Token.SourceLength`, `LiteralSpans`, comment trivia, the
AST's header-end positions) and models nothing of its own.

- **D1 — one seam, `Refactoring/SourceRegion.cs`** (`internal`): `SourceLines` (lines, breaks, `DocumentLineBreak` via
  `LineDiff.Split`; `Indentation(line)`, `IsBlank(line)`); `Extent.EndLine(stmt, tokens, lines)` — `max(stmt.LineEnd, …)` over the end line of every token with
  `Position ≥ stmt`'s start offset, start line ≤ `LineEnd` and `Position + Length` on a later line (the multi-line
  last-token fact; `Token.Position`/`Length` at `Token.cs:199/280`) [CORRECTED: written as a monotone `max` restricted
  to the statement's own tokens, so the helper becomes an identity once the parser fact is fixed — no second model]; `Region.Slice(first, last)` — whole lines, verbatim (trailing comments, blank lines, own-line
  comments included); `Region.Reindent(lines, delta, literalLines)` — every non-blank line's leading whitespace changed
  by `delta` (negative delta strips up to `|delta|`; a line with less indentation than that keeps column 0 and the
  provider's hand test pins that case), a line in `literalLines` byte-identical, a blank line byte-identical;
  `InlineComment(line)` — the `IsInline` comment trivia of that line, or null. Providers hold NO line splitting of their
  own; `SharpySourceGenerator.GetIndentation/GetIndentUnit/GetNodeSourceText` become thin calls on `SourceLines`, and
  `FormatFunctionDef/FormatPropertyDef` take the line break as a parameter (no default).
- **D2 — a re-emitted statement's edit replaces WHOLE lines:** range `(LineStart−1, 0)` → `(EndLine(stmt), 0)` exclusive
  (the line after the true last line, column 0) and the new text ends with the document's break. This kills the
  doubled-indent cell (8/10/11), the dropped trailing comment (6) and the split literal (5/13) at one stroke, and it is
  safe because no two statements share a line (measured). For the LAST line of the document (no break after it) the
  range ends at the line's end and the new text omits the final break.
- **D3 — a line that starts inside a multi-line literal is byte-identical under any re-indent** (offset 0 even when the
  region moves): shifting it changes the string's VALUE. Rejected: shift literal lines with the region (prettier, wrong
  program). The formatter's rule (`LiteralSpans`, P22b) is the same rule; one source of the line set.
- **D4 — Organize Imports moves UNITS, not renderings:** a unit = the own-line comment lines above an import (from the
  previous unit's last line + 1, blank lines excluded) + the import's lines through its true end; units are sorted by the
  import's key as today (stdlib group, blank separator, project group; decorated imports pinned verbatim as today;
  `import`-before-`from` within a group) and written verbatim with the document's break; the replaced range ends at the
  LAST import's true end line + 1 — the blank lines after the block are untouched (cells 1, 22). An unused import's
  (SPY0452) lines are dropped and its own-line comments stay (written before the unit that takes its slot, or last).
  Blank lines INSIDE the block remain the action's layout (today's behaviour; this is not P50's formatter rule).
  Rationale: the comment above an import belongs to that import (the formatter's anchor rule, `Compiler/Formatting/CommentAnchors.cs` [CORRECTED: lives in `Formatting/`, not `Pretty/`]: an
  own-line comment anchors to the following code token), so it travels with it.
  [CORRECTED: region start] The replaced range STARTS at the first import's `LineStart` exactly as today's `GetImportRange`
  (`OrganizeImportsProvider.cs:352`) does, so own-line comments above the FIRST import (a file header) are outside the
  region and never move; the first unit therefore has no leading comment lines. The edge cell this creates — a comment
  directly above the first import when that import is not first after sorting (`# helpers / from os.path import join /
  import sys` → `import sys` lands under `# helpers`) — is a hand-test cell of Phase 2 Task 3 with (a) "stays, outside
  the region" as the pinned behaviour (recommended: a file header must never move; the `comment` oracle holds either way).
- **D5 — a deleted statement's trailing comment is deleted with it** (Inline variable's declaration line, the Remove
  unused import quick fix, an unused import under Organize Imports): the comment describes code that no longer exists.
  Rejected: keep it as an orphan own-line comment. The sweep's `comment` oracle exempts exactly the inline comments of
  the lines an action DELETES as whole statements (declared removals, computed by the sweep from the request, never
  read from the provider). Own-line comments ABOVE a deleted statement are never deleted (D4).
- **D6 — Convert forms re-spell headers and MOVE bodies:** `if`/`elif`/`else`/`match`/`case` header lines are rewritten
  (as today), each with its inline comment re-attached from `InlineComment(HeaderLineEnd | ElseHeaderLine)`; a body is
