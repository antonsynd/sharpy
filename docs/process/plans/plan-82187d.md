## Context

P21g (plan-cbdf79 @ 8ff3417de) made every import spelling bind its module-level name through ONE seam
(`ImportResolver.BindImportName`, ProjectCompiler Phase 4), made a from-import's identity the exported symbol
(K1, #2359), and recorded WHICH names a star import bound (`SemanticInfo.GetStarImportBoundNames`, #2371) so the
emitter stopped reading the module's export list. Its verify rounds found that the seam's DECISION is still not what
every consumer of a module binding reads (charter §3.20e, R-JF):

- **(i)** the recorded star fact is consumed for qualification only — the per-name `CodeGenInfo` is computed for
  `fromImport.Names`, which a star has none of, so a star-imported VARIABLE read anywhere is SPY0909 (#2385); and
  the fact OVER-REPORTS a module variable the checker took over, so the emitter's own two-kind name list is what
  keeps star × var correct today (#2385 M1);
- **(ii)** the emitter qualifies a same-module member only when its name is in a hand list of two statement kinds
  (`FunctionDef`, `VariableDeclaration`), so a module PROPERTY read from a type body is CS0103 behind SPY0908 (#2386);
  and the export table (`ModuleLoader.ExtractExportedSymbol`) has no `PropertyDef` arm, so a module property is
  unreachable from another module on every spelling (the #2131 cell re-homed on #2386);
- **(iii)** a from-import's identity is the SPELLED `"{sourceModule}.{name}"`, so one declaration reached through
  two module spellings (a re-export) is two identities and importing it twice is SPY0204 (#2389; owner ruling R-JK).

One contract, three consumers, broken along axes the P21g generators never enumerated: the star arm has no
use-position or kind axis beyond "the local wins", the qualification matrix has no property kind and no read-site
axis, the import-binding sub-matrix has no provenance axis.
