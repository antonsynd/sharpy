## Design Decisions

1. **Loop transfer: one recorded binding, the `is`-chain for a hosting `match`, the walker deleted.** A validator pass with a loop stack records, per `BreakStatement`/`ContinueStatement`, `LoopTransferTarget(Statement TargetLoop, bool CrossesMatch)` and, per `MatchStatement`, `MatchHostsLoopTransfer = true` when a transfer inside one of its arms targets a loop OUTSIDE the match (a `break` in a nested loop inside the arm does not count). Both are node-keyed `SemanticInfo` dictionaries (`_loopTransferTargets`, `_matchHostsLoopTransfer`) with `MergeFrom` lines. The emitter: `GenerateMatch` takes `GenerateMatchAsIsChain` when the fact is set (in addition to the existing "a guard hoists" trigger) — the `is`-chain manufactures no `switch`, so a plain C# `break`/`continue` targets the enclosing loop (verified by `brk_break_for_guardhoist` at HEAD); `GenerateBreak` looks the target loop up in an emitter dictionary `_loopElseFlags` (loop node → flag name, populated by `GenerateFor`/`GenerateWhile`/`GenerateWhileWithElse` when the loop has an `else`) and emits `{ flag = false; break; }` itself. `TransformLoopBodyForElse`, `TransformStatementForLoopElse`, `GenerateBreakWithFlag` (`ControlFlow.cs:25`), `BreakWithFlagStatement` (`Statement.cs:180`), its `AstVisitor`/`AstDumper` arms and `ControlFlowGraphBuilder.BuildBreakWithFlag` are deleted — the flag rewrite was the only reason a CodeGen-synthesized node lived in the parser's AST namespace. Verifier note: `match` is the ONLY construct that manufactures a C# `switch` (`grep -rn 'SwitchStatement(' src/Sharpy.Compiler/CodeGen` = 1 site, `Patterns.cs:135` @ b9ae01c4f), and every other manufactured C# loop (`ControlFlow.cs:448/471/494/519/648/671/712/735/753`, `Statements.cs:814` `yield from`) is a user loop's own lowering or has no user statements inside — so the host axis is complete at `match`. Record `MatchHostsLoopTransfer` for `break` only (or keep it for both but expect snapshot churn): `continue` inside a C# `switch` already targets the loop (measured `0 1 3 done`, python agrees), so a `continue`-only match gains nothing from the `is`-chain. **Why not `goto`:** a label after the loop's `else` needs CS0164-safe emission (unused label = warning = error), a second manufactured name per loop, and the loop-else flag still needs the binding fact; the `is`-chain already exists, is measured correct for `break`, and is the shape P5 re-cuts anyway. Trade-off accepted: a `match` hosting a `break` loses C#'s `switch` definite-return analysis — irrelevant inside a loop body (the loop's successor decides returns). Recorded as the choice under the #1816 body's "or" clause.
