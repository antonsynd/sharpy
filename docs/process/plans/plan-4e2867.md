# Optional-needle membership: `T | None in container`

## Context

#2635: a value-typed `T | None` needle is refused (SPY0222) by `in`/`not in`, where CPython 3.15 answers `False`/`True` for `None`. Found when `socket.error.errno` became `int | None` (PR #2636).

## Current State

Measured @ b0241f778 (CPython 3.15.2, oracle required) by stage 0, `OptionalMembershipDifferentialTests`: 15 payloads, 3960 cases (1572 compared with CPython, 2388 hand-expected), 1188 divergent cells in 12 rows of `optional-membership-differential-allowlist.txt` (`<container>/<Plain|NoneNeedle>`, each pinning its exact cells). Three runs, 1 passed each.

- Value payloads (`int8`…`uint64`, `float32/64`, `decimal`, `bool`, `tuple[int, int]`) as `T | None`: SPY0222 in all 9 equality-scan containers (tuple, list, set, frozenset, dict, keys, values, `__contains__` class, range).
- The literal `None` needle into a non-optional slot: SPY0222 at both arms (correct by ruling A), except `bytes` (SPY0908, #2647). Into an optional element type it runs and matches CPython (the named control below).
- Reference payloads (`str | None`, class `| None`) already run and print `False` for `None`, because `NullableType.IsAssignableTo` (`SemanticType.cs:749`) admits only a reference payload.
- `str | None in str`: runs, and `None` throws `ArgumentNullException` where CPython raises TypeError (row `Str/NoneNeedle`).
- `bytes` (#2647): the checker decides no needle slot. `None`, `int | None`, `int64`, `str`, float and class needles reach Roslyn (SPY0908 CS1503): rows `Bytes/Plain`, `Bytes/NoneNeedle`. `bytes` is a registry `UserDefinedType` (`TypeChecker.Expressions.Literals.cs:1005`), so no arm of `ResolveMembershipElementType` reaches it; the same holds for the other CLR-backed non-generic containers (`ipaddress.IPv4Network`: `"x" in net` is SPY0908).
- Controls: `x == 1` runs on every value payload `| None`; `x in list[int | None]` runs; `T?` (Optional) refuses `==` and `in` alike.

## Adversarial Review (pre-mortem)

- **Alternative root cause:** a store-seam rule rather than membership. Discriminator: `b: bool = x in [1]` gives SPY0222 while `x == 1` runs, so the needle check (`ClassifyMembership`, `:1578`) refuses.
- **Alternative layer:** a Core extension `Contains(T?)` per receiver (rung 2) cannot reach user `__contains__` classes or the tuple projection, and cannot tell `string?` from `string`. So the kind is a checker fact, and the runtime body is rung 2.
- **How the fix could be inert:** the checker accepts but the emitter still prints `y.Contains(x)` (CS1503 → SPY0908). The binary site (`:77`) and the chain site (`:1476`) share `ClassifyMembership`, so one site cannot drift from the other.
- **Before/after by direction:** newly refused programs are `str`, float, class and `int64` needles into `bytes`, which were SPY0908 before (ICE → diagnostic). D3's arm also gives a slot to every other CLR-backed non-generic container with a public `Contains` (`IPv4Network`, `IPv6Network`, argparse `Namespace`, `EmailMessage`); T1 runs their needles at the base and classifies each newly refused one. `b"a" in b"ab"` runs today and must keep running (D3's `bytes` slot). `str | None in str` keeps running; `None` changes from a CLR throw to TypeError. The literal `None` keeps SPY0222 into a non-optional slot (ruling A); in `bytes` it changes from SPY0908 to SPY0222.
- **Blast radius:** Compiler.Tests (fixtures, Differential, GapDiscovery sweeps), Stdlib.Tests, Cli.Tests, LSP `FrontEndParityTests`.
- **Generated artifacts touched:** spy-stdlib and spy-test C# (expect no diff), regenerated at T1's end.

## Design Decisions

- **D1. Lift the value needle.** In `ClassifyMembership` (`TypeChecker.Expressions.Operators.cs:1578`), only after the existing `IsArgumentAssignable(needleType, elementType)` test fails, a `NullableType` needle whose underlying type `IsArgumentAssignable` to the element slot is accepted. A needle the slot already holds (`x: int | None` into `list[int | None]`, where `None` is a member) keeps today's plain path.
  - For a non-subsequence container with a value payload, `ClassifyMembership` returns `OperatorLoweringKind.MembershipNoneIsFalse`. The binary site records it with `SetOperatorLowering` (`SemanticInfo.cs:2114`; `_operatorLowerings` is already in `MergeFrom`, `:2465`); the chain site records it in its `ComparisonLinkLowering` (dead until #2648).
  - The emitter `In`/`NotIn` arm (`RoslynEmitter.Expressions.Operators.cs:186`) reads the kind and emits `Builtins.ContainsOptional(x, y, static (c, n) => c.Contains(n))`, negated for `not in`. The container is projected exactly as today.
  - The Core helper (a new file beside `Map.cs`) is `needle.HasValue && contains(container, needle.Value)`, generic over `T : struct`.
  - Rung 2 for the runtime body. Rung 1 cannot carry it: a CLR receiver's `Contains(T)` will not take a `T?` argument. The choice of helper is a checker fact (needle type × container), so it is recorded rather than decided in the emitter (Rule 2).
  - **Predicate:** `ClassifyMembership` is the only place that decides either membership kind, and the emitter's `In` arm reads it; no type test is added in `CodeGen/`.
  - A reference payload in an equality-scan container records nothing: `Contains(null)` already answers `False`, measured green by stage 0.
  - **The literal `None`** (ruling A) gets no lowering. Into a non-optional slot it keeps today's SPY0222 at both arms; into an optional element it is plain membership, unchanged (the named control).
- **D2. Subsequence containers raise.** A container is a subsequence container when its CLR type (`BuiltinType.ClrType`, or `UserDefinedType.Symbol.ClrType` for `bytes`) has a public `Contains` that takes its own type (`string.Contains(string)`, `Bytes.Contains(Bytes)`). This is decided by CLR reflection through `ClrTypeHelper`, not by name (rung 3).
  - For such a container, any `NullableType` needle (value or reference payload) records `MembershipNoneRaises`.
  - The emitter emits `Builtins.ContainsNoneRaises(x, y, static (c, n) => c.Contains(n))`. Overloads for a value needle and a reference needle throw `TypeError` on `None`, with CPython's text (message is DEVIATION by default). This applies ruling 2.
  - **Predicate:** `x: str | None = None; x in "abc"` raises a TypeError that `except TypeError:` catches.
- **D3. The bytes slot (#2647).** `ResolveMembershipElementType` (`:1617`) resolves `bytes`' needle slots from its public single-argument `Contains` overloads (`int`, `bytes`) instead of returning none. The CLR arm at `:1684` matches only a `BuiltinType`; `bytes` is a `UserDefinedType` whose `Symbol.ClrType` is `Sharpy.Bytes`, so the arm is extended to that case, read through `ClrTypeHelper`, and generalized from `FirstOrDefault` to the overload set (a needle is accepted when it is assignable to any overload's slot). It is a needle-type decision, not a name rule, so it reaches every CLR-backed non-generic container (Adversarial Review, by direction).
  - The spec's Container kinds table names `int` as the `bytes` slot; the `bytes` slot (`b"a" in b"ab"`: runs, `True`, as CPython) needs that row amended (D5).
  - A `str` or `int64` needle is then refused with SPY0222 and its cast steer (`membership-needle-type-mismatch`). Literal `None` into `bytes` is refused SPY0222, as it is everywhere else (ruling A).
  - **Predicate:** `n: int64 = 1; n in bytes([1])` is SPY0222, never SPY0908; `bytes([97]) in bytes([97, 98])` still prints `True`.
- **D4. Evaluation order.** Both helpers take the needle before the container, so lifted cells evaluate `x` then `y`, as Python does. This does **not** settle #2645: every non-lifted cell keeps `y.Contains(x)` (container first). #2645 stays open, and its cure can route the plain arm through the same helper shape.
- **D5. Spec.** In `docs/language_specification/membership_operators.md` › Needle Type, add a "None needles" paragraph. A `T | None` needle is accepted: `None` is no element's equal, and TypeError for `str`/`bytes` (D2). The literal `None` is refused unless the element type is optional (ruling A). Use executed examples whose output differs under the bug.
  - In `docs/deviations.yaml`, state that `membership-needle-type-mismatch` covers the literal `None` into a non-optional slot (ruling A) and not a `T | None` needle (rulings 1–2).
  - That row's rationale changes from "can never be a member" to ruling B's. The slot holds `int`, and a needle must convert implicitly to the slot type. This is a deliberate difference from Python (CPython: `True in range(3)` and `Decimal(1) in range(1, 3)` are True), and the cure is a cast. Its example names a `bool` or `decimal` needle.
  - Owner question: CLOSED by ruling B.
  - Owner question (OPEN): the Container kinds row for `bytes` reads `int`, while `b"a" in b"ab"` runs today and CPython answers `True`. Amend the row to `int`, or `bytes` (subsequence test), which D3 implements; the alternative is refusing a `bytes` needle (a worked → refused regression). Rule 7 leaves this to the owner.
