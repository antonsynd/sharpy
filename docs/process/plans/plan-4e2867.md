# Optional-needle membership: `T | None in container`

## Context

#2635: a value-typed `T | None` needle is refused (SPY0222) by `in`/`not in`, where CPython 3.15 answers `False`/`True` for `None`.

## Current State

Stage 0 (`OptionalMembershipDifferentialTests`) @ 8525b660f, CPython 3.15.2 required: 31 payloads, 25368 cases (12744 compared, 12624 hand-expected), 6302 divergent in the 28 rows of `optional-membership-differential-allowlist.txt`; 1 passed.

- Value payloads (the numerics, `decimal`, `bool`, `bytes`, `tuple[int, int]`, a user `struct`) as `T | None`: SPY0222 in all 14 element-typed containers and in `range`.
- Four types are C# value types but not `IsValueType` (`SemanticType.cs:206`, `:490`): an int-backed enum (`Color`), a generic struct (`GS[int]`), a `struct`-constrained type parameter, `Self` in a struct. Their `T | None` passes `NullableType.IsAssignableTo` (`:749`) into a `T` slot: SPY0908 as a needle, at every store, and after `if d is not None:`.
- `T | None` on a type parameter bound to a value type is plain `T` (`TypeSubstitution.cs:50`), also under `[T: struct]` (C# `Nullable<T>`): `None` and an `int | None` argument are refused (SPY0229, SPY0220).
- Reference payloads as `| None` pass `:749`; their `None` reaches `Contains(null)`: `False` in the scan containers; `ArgumentNullException` in `Counter` and `str` (CPython: `False`, TypeError); `NullReferenceException` in the IP networks, `False` in `EmailMessage` (CPython: `AttributeError`). A string-backed enum (`Tone`) is SPY0222 into `str`; into `Namespace`/`EmailMessage` its `None` throws `NullReferenceException` in the emitted `op_Implicit`.
- The CLR-backed non-generic containers (#2647: `bytes`, the IP networks, argparse `Namespace`, `EmailMessage`) are registry `UserDefinedType`s (`TypeChecker.Expressions.Literals.cs:1005`) no arm of `ResolveMembershipElementType` decides: a needle their `Contains` cannot take is SPY0908.

## Design Decisions

- **D1. Lift the needle.** `ClassifyMembership` (`TypeChecker.Expressions.Operators.cs:1578`) decides in order: D2's subsequence test; the existing `IsArgumentAssignable(needleType, elementType)` test (plain path, unchanged: `int | None` into `list[int | None]`, M4); the lift: a `NullableType` needle whose underlying type `IsArgumentAssignable` to the slot is accepted.
  - A lifted value-type needle (`NullableType.IsValueType`, so D7's types too) returns `OperatorLoweringKind.MembershipNoneIsFalse`, recorded by the binary site with `SetOperatorLowering` (`SemanticInfo.cs:2148`; `_operatorLowerings` is in `MergeFrom`, `:2514`) and by the chain site in its `ComparisonLinkLowering` (dead until #2648).
  - The emitter `In`/`NotIn` arm (`RoslynEmitter.Expressions.Operators.cs:186`) reads the kind and emits `Builtins.ContainsOptional(x, y, static (c, n) => c.Contains(n))`, negated for `not in`. The Core helper is `needle.HasValue && contains(container, needle.Value)` over `T : struct`.
  - Rung 2 for the runtime body (rung 1: a CLR `Contains(T)` takes no `T?`); the helper choice is a checker fact, so it is recorded (Rule 2).
  - **Predicate:** `ClassifyMembership` alone decides either membership kind, and the emitter's `In` arm reads it (through `OperatorLoweringOf`); no type test is added in `CodeGen/`.
  - A reference needle, lifted (`Tone | None` into a `str` slot, D8) or not, records nothing: the receiver's `Contains(null)` answers (D6).
  - The literal `None` gets no lowering: SPY0222 into a non-optional slot at both arms (ruling A), plain membership into an optional element.
- **D2. Subsequence containers raise.** A subsequence container's CLR type (`BuiltinType.ClrType`, or `UserDefinedType.Symbol.ClrType` for `bytes`) has a public `Contains` taking its own type (`string.Contains(string)`, `Bytes.Contains(Bytes)`): decided by reflection through `ClrTypeHelper`, not by name (rung 3).
  - There a `NullableType` needle whose underlying type is assignable to a slot (value or reference) records `MembershipNoneRaises`, before the assignability test: `str | None` into `str` passes that test today and would return early.
  - Emitted as `Builtins.ContainsNoneRaises(x, y, static (c, n) => c.Contains(n))`; a value-needle and a reference-needle overload throw `TypeError` on `None` (ruling 2; message DEVIATION by default).
  - **Predicate:** `x: str | None = None; x in "abc"` raises a TypeError that `except TypeError:` catches; so does `t: Tone | None = None; t in "abc"`.
- **D3. The CLR-backed slot (#2647).** `ClassifyMembership` resolves the needle slots of a CLR-backed non-generic container from its public single-argument `Contains` overloads: a slot-set sibling of `ResolveMembershipElementType` (`:1617`), whose CLR arm (`:1684`) matches only a `BuiltinType` and takes `FirstOrDefault`. It reads `Symbol.ClrType` through `ClrTypeHelper` and accepts a needle assignable to any slot.
  - `ResolveMembershipElementType` still returns none for them, so the site's store (`:62`) pushes no slot.
  - `bytes`' slots are `int` and `bytes` (ruling C; D5).
  - A needle no overload takes is SPY0222 with its cast steer (`membership-needle-type-mismatch`); so is the literal `None` (ruling A).
  - **Predicate:** `n: int64 = 1; n in bytes([1])` and `"x" in IPv4Network("10.0.0.0/8")` are SPY0222, not SPY0908; `bytes([1]) in bytes([1, 2])` and `1 in bytes([1, 2])` print `True`; `None in EmailMessage()` is SPY0222.
- **D4. Evaluation order.** Both helpers take the needle before the container: lifted cells evaluate `x` then `y`, as Python does. Non-lifted cells keep `y.Contains(x)`; #2645 stays open.
- **D5. Spec.** `docs/language_specification/membership_operators.md` › Needle Type gains a "None needles" paragraph: a `T | None` needle is accepted (`None` equals no element; TypeError for `str`/`bytes`, D2; the receiver's answer for a CLR container, D6); the literal `None` is refused unless the element type is optional (ruling A). Its examples run and differ under the bug. The Container kinds row for `bytes` reads `int` or `bytes` (ruling C).
  - `docs/deviations.yaml`: `membership-needle-type-mismatch` covers the literal `None` into a non-optional slot (ruling A), not a `T | None` needle. Its rationale becomes ruling B's (the slot holds `int`, a needle must convert implicitly, a cast cures it; `True in range(3)` is True in Python); its example names a `bool` or `decimal` needle.
- **D6. Receivers answer `None` as CPython does.** Rung 2, in Stdlib C#: `Counter.Contains(null)` returns `False`; `IPv4Network.Contains`, `IPv6Network.Contains` and `EmailMessage.Contains` raise `AttributeError` on `null` (message DEVIATION by default). `Namespace.Contains(null)` already returns `False`.
  - **Predicate:** `a: IPv4Address | None = None; a in IPv4Network("10.0.0.0/8")` raises an `AttributeError` that `except AttributeError:` catches; `s: str | None = None; s in Counter[str](["a"])` prints `False`.
- **D7. Value-ness is the emitted C# type's (R-NY, ruling G).** `IsValueType` is true for a `UserDefinedType` of `TypeKind.Struct`, or of `TypeKind.Enum` unless `Symbol.IsStringEnum` (`SemanticType.cs:490`; set at declaration, `NameResolver.Declarations.cs:432`); for a `GenericType` whose `GenericDefinition` is a struct; for a `TypeParameterType` with a `struct` constraint; for a `SelfType` whose `DeclaringType` is a value type by the first rule. Two readers change:
  - `TypeSubstitution.cs:50` keeps `T | None` when `T` is `struct`-constrained (C# `Nullable<T>`). An unconstrained `T | None` over a value type stays `T` (#1797).
  - The `struct` constraint (`GenericTypeInferenceService.cs:712`) refuses a `T | None` binding with SPY0237, as C# does (CS0453). Without it D7 turns `h[T: struct](d)`, `d: Color | None`, from SPY0237 into SPY0908.
  - **Predicate:** for `d` a `Color | None`, a `GS[int] | None`, a `Self | None` in a struct or a `T | None` under `[T: struct]`: `g(d)` into the plain slot is SPY0220 and `return d` SPY0260, never SPY0908; `if d is not None: g(d)` runs; `d in [..]` prints `False` for `None` (D1). `g[T: struct](x: T | None)` takes `None`. `Tone | None in [Tone.A]` still runs.
- **D8. A string-backed enum converts `None` to `None`.** The emitted `implicit operator string` (`RoslynEmitter.TypeDeclarations.cs:1473`) returns null for a null operand instead of dereferencing it: the generated class's body (`SyntaxFactory` only, no type decision; no lower rung declares the conversion). Every `Tone | None` to `str` conversion changes: `None` flows on where it threw. No `.expected.cs` snapshot contains the operator.
  - **Predicate:** `t: Tone | None = None`: `t in ns` (argparse `Namespace`) prints `False`; `t in EmailMessage()` raises `AttributeError` (D6).
