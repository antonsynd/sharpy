# Optional-needle membership: `T | None in container`

## Context

#2635: a value-typed `T | None` needle is refused (SPY0222) by `in`/`not in`, where CPython 3.15 answers `False`/`True` for `None`. Found when `socket.error.errno` became `int | None` (PR #2636).

## Current State

Measured @ bc188462e (CPython 3.15.2, oracle required) by stage 0, `OptionalMembershipDifferentialTests`: 15 payloads, 3960 cases (2562 compared with CPython, 1398 hand-expected), 2358 divergent cells in 12 rows of `optional-membership-differential-allowlist.txt` (`<container>/<Plain|NoneNeedle>`, each pinning its exact cells). Three runs, 1 passed each.

- Value payloads (`int8`…`uint64`, `float32/64`, `decimal`, `bool`, `tuple[int, int]`) as `T | None`: SPY0222 in all 9 equality-scan containers (tuple, list, set, frozenset, dict, keys, values, `__contains__` class, range).
- The literal `None` needle: SPY0222 in every container, where CPython answers `False`/`True` (TypeError for `str`/`bytes`). The chain arm refuses it too (`None is None in [a]`: SPY0222 on the `in` link).
- Reference payloads (`str | None`, class `| None`) already run and print `False` for `None`, because `NullableType.IsAssignableTo` (`SemanticType.cs:749`) admits only a reference payload.
- `str | None in str`: runs, and `None` throws `ArgumentNullException` where CPython raises TypeError (row `Str/Optional`).
- `bytes` (#2647): the checker decides no needle slot. `None`, `int | None`, `int64`, `str`, float and class needles reach Roslyn (SPY0908 CS1503): rows `Bytes/Plain`, `Bytes/NoneNeedle`.
- Controls: `x == 1` runs on every value payload `| None`; `x in list[int | None]` runs; `T?` (Optional) refuses `==` and `in` alike.

## Adversarial Review (pre-mortem)

- **Alternative root cause:** a store-seam rule rather than membership. Discriminator: `b: bool = x in [1]` gives SPY0222 while `x == 1` runs, so the needle check (`ClassifyMembership`, `:1578`) refuses.
- **Alternative layer:** a Core extension `Contains(T?)` per receiver (rung 2) cannot reach user `__contains__` classes or the tuple projection, and cannot tell `string?` from `string`. So the kind is a checker fact, and the runtime body is rung 2.
- **How the fix could be inert:** the checker accepts but the emitter still prints `y.Contains(x)` (CS1503 → SPY0908). The binary site (`:77`) and the chain site (`:1476`) share `ClassifyMembership`, so one site cannot drift from the other.
- **Before/after by direction:** newly refused programs are `str`, float, class and `int64` needles into `bytes`, which were SPY0908 before (ICE → diagnostic). `str | None in str` keeps running; `None` changes from a CLR throw to TypeError. `None in xs` changes from SPY0222 to running.
- **Blast radius:** Compiler.Tests (fixtures, Differential, GapDiscovery sweeps), Stdlib.Tests, Cli.Tests, LSP `FrontEndParityTests`.
- **Generated artifacts touched:** spy-stdlib and spy-test C# (expect no diff), regenerated at T1's end.

## Design Decisions

- **D1. Lift the value needle.** In `ClassifyMembership` (`TypeChecker.Expressions.Operators.cs:1578`), a `NullableType` needle whose underlying type `IsArgumentAssignable` to the element slot is accepted.
  - For a non-subsequence container with a value payload, it records `OperatorLoweringKind.MembershipNoneIsFalse` with `SetOperatorLowering` (`SemanticInfo.cs:2114`; `_operatorLowerings` is already in `MergeFrom`, `:2465`). The chain link records the same kind in its `ComparisonLinkLowering`.
  - The emitter `In`/`NotIn` arm (`RoslynEmitter.Expressions.Operators.cs:186`) reads the kind and emits `Builtins.ContainsOptional(x, y, static (c, n) => c.Contains(n))`, negated for `not in`. The container is projected exactly as today.
  - The Core helper (a new file beside `Map.cs`) is `needle.HasValue && contains(container, needle.Value)`, generic over `T : struct`.
  - Rung 2 for the runtime body. Rung 1 cannot carry it: a CLR receiver's `Contains(T)` will not take a `T?` argument. The choice of helper is a checker fact (needle type × container), so it is recorded rather than decided in the emitter (Rule 2).
  - **Predicate:** `ClassifyMembership` is the only place that writes either membership kind, and the emitter's `In` arm reads it; no type test is added in `CodeGen/`.
  - A reference payload in an equality-scan container records nothing: `Contains(null)` already answers `False`, measured green by stage 0.
  - **The literal `None`** (owner rulings 4–5) takes the same kinds. Its needle is emitted as a typed null through the existing typed-null fact (`SetArgumentSlotCast`), cast to the slot's nullable type, so the helper call needs no type decision in the emitter. A slot that already holds None (`list[int | None]`) is plain membership, unchanged.
- **D2. Subsequence containers raise.** A container is a subsequence container when its CLR type has a public `Contains` that takes its own type (`string.Contains(string)`, `Bytes.Contains(Bytes)`). This is decided by CLR reflection through `ClrTypeHelper`, not by name (rung 3).
  - For such a container, any `NullableType` needle (value or reference payload) records `MembershipNoneRaises`.
  - The emitter emits `Builtins.ContainsNoneRaises(x, y, static (c, n) => c.Contains(n))`. Overloads for a value needle and a reference needle throw `TypeError` on `None`, with CPython's text (message is DEVIATION by default). This applies ruling 2.
  - **Predicate:** `x: str | None = None; x in "abc"` raises a TypeError that `except TypeError:` catches.
- **D3. The bytes slot (#2647).** `ResolveMembershipElementType` (`:1617`) resolves `bytes`' needle slots from its public single-argument `Contains` overloads (`int`, `bytes`) instead of returning none. The CLR arm at `:1684` is generalized from `FirstOrDefault` to the overload set, so it is a needle-type decision, not a name rule.
  - A `str` or `int64` needle is then refused with SPY0222 and its cast steer (`membership-needle-type-mismatch`). Literal `None` is refused SPY0222 at every container.
  - **Predicate:** `n: int64 = 1; n in bytes([1])` is SPY0222, never SPY0908.
- **D4. Evaluation order.** Both helpers take the needle before the container, so lifted cells evaluate `x` then `y`, as Python does. This does **not** settle #2645: every non-lifted cell keeps `y.Contains(x)` (container first). #2645 stays open, and its cure can route the plain arm through the same helper shape.
- **D5. Spec.** In `docs/language_specification/membership_operators.md` › Needle Type, add a "None needles" paragraph covering D1's rule for `T | None` and the literal `None` (`None` is no element's equal), and D2's TypeError. Use executed examples whose output differs under the bug.
  - In `docs/deviations.yaml`, state that `membership-needle-type-mismatch` does not cover a None needle (rulings 4–5).
  - That row's rationale ("can never be a member") and its example must also acknowledge `bool` and `decimal` needles into `range`/`bytes`. CPython says `True in range(3)` is True and `Decimal(1) in range(1, 3)` is True, so the refusal there drops a real member.
  - **Owner question** (no expectation changes now): keep refusing `bool`/`decimal` needles into an `int` slot (record it as a deviation with the true rationale), or admit them?
