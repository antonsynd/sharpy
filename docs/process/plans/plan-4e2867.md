# Optional-needle membership: `T | None in container`

## Context

#2635: a value-typed `T | None` needle is refused (SPY0222) by `in`/`not in`, where CPython 3.15 answers `False`/`True` for `None`. Found when `socket.error.errno` became `int | None` (PR #2636).

## Current State

Measured @ fc189aa97 (CPython 3.15.2, oracle required) by stage 0, `OptionalMembershipDifferentialTests`: 18 payloads, 15120 cases (7752 compared with CPython, 7368 hand-expected), 4016 divergent cells in 28 rows of `optional-membership-differential-allowlist.txt` (`<container>[OfOptional]/<Plain|NoneNeedle>`, each pinning its exact cells).

- Value payloads (`int8`…`uint64`, `float32/64`, `decimal`, `bool`, `tuple[int, int]`) as `T | None`: SPY0222 in every element-typed container (14: the 8 Python kinds plus `Counter`, `OrderedDict`, `ChainMap`, `defaultdict`, `frozendict`, `deque`) and in `range`.
- The literal `None` into a non-optional slot: SPY0222 (correct by ruling A), except the CLR-backed fixed-slot containers: SPY0908 in `bytes`, runs in argparse `Namespace` and `EmailMessage`, `NullReferenceException` in `IPv4Network`/`IPv6Network`. Into an optional element it runs and matches CPython (rows `*OfOptional` green, except `Counter`).
- Reference payloads (`str`, class, `bytes`, `IPv4Address`, `IPv6Address`) as `| None` pass `NullableType.IsAssignableTo` (`SemanticType.cs:749`). Their `None` reaches the receiver's `Contains(null)`: `False` for the scan containers, but `ArgumentNullException` in `Counter`, `NullReferenceException` in `IPv4Network`/`IPv6Network`, `False` in `EmailMessage` (CPython: `AttributeError` for these three), `ArgumentNullException` in `str` (row `Str/NoneNeedle`; CPython TypeError).
- CLR-backed non-generic containers (#2647: `bytes`, `IPv4Network`, `IPv6Network`, argparse `Namespace`, `EmailMessage`) are registry `UserDefinedType`s (`TypeChecker.Expressions.Literals.cs:1005`), so no arm of `ResolveMembershipElementType` decides their needle: every needle their `Contains` cannot take is SPY0908. `b"a" in b"ab"` and `97 in b"ab"` run and print `True`.
- Out of contract: `Counter[T | None]` with a `None` element throws `ArgumentNullException` at construction (rows `CounterOfOptional/*`, #2651).
- Controls: `x == 1` runs on every value payload `| None`; `T?` (Optional) refuses `==` and `in` alike.

## Adversarial Review (pre-mortem)

- **Alternative root cause:** a store-seam rule. Discriminator: `b: bool = x in [1]` gives SPY0222 while `x == 1` runs, so the needle check (`ClassifyMembership`, `:1578`) refuses.
- **Alternative layer:** a Core `Contains(T?)` per receiver (rung 2) cannot reach user `__contains__` classes or the tuple projection, nor tell `string?` from `string`; the kind is a checker fact, the runtime bodies rung 2 (D6 is rung 2 outright).
- **How the fix could be inert:** the checker accepts but the emitter still prints `y.Contains(x)` (CS1503 → SPY0908). The binary site (`:77`) and the chain site (`:1476`) share `ClassifyMembership`.
- **Before/after by direction:** newly refused: needles a CLR-backed container's `Contains` cannot take (SPY0908 → SPY0222; ICE → diagnostic) and the literal `None` into `Namespace`/`EmailMessage`, which runs today (`False`; ruling A refuses it; T1 records each). `b"a" in b"ab"`, `97 in b"ab"` and `str | None in str` keep running.
- **Blast radius:** Compiler.Tests (fixtures, Differential, GapDiscovery sweeps), Stdlib.Tests, Cli.Tests, LSP `FrontEndParityTests`.
- **Generated artifacts touched:** spy-stdlib and spy-test C# (expect no diff), regenerated at T1's end.

## Design Decisions

- **D1. Lift the value needle.** In `ClassifyMembership` (`TypeChecker.Expressions.Operators.cs:1578`), only after the existing `IsArgumentAssignable(needleType, elementType)` test fails, a `NullableType` needle whose underlying type `IsArgumentAssignable` to the element slot is accepted. A needle the slot already holds (`x: int | None` into `list[int | None]`, where `None` is a member) keeps today's plain path; the `*OfOptional/Optional` cells (`None` → `True`) pin that order.
  - For a non-subsequence container with a value payload, `ClassifyMembership` returns `OperatorLoweringKind.MembershipNoneIsFalse`. The binary site records it with `SetOperatorLowering` (`SemanticInfo.cs:2114`; `_operatorLowerings` is already in `MergeFrom`, `:2465`); the chain site records it in its `ComparisonLinkLowering` (dead until #2648).
  - The emitter `In`/`NotIn` arm (`RoslynEmitter.Expressions.Operators.cs:186`) reads the kind and emits `Builtins.ContainsOptional(x, y, static (c, n) => c.Contains(n))`, negated for `not in`. The container is projected exactly as today.
  - The Core helper (a new file beside `Map.cs`) is `needle.HasValue && contains(container, needle.Value)`, generic over `T : struct`.
  - Rung 2 for the runtime body. Rung 1 cannot carry it: a CLR receiver's `Contains(T)` will not take a `T?` argument. The choice of helper is a checker fact (needle type × container), so it is recorded rather than decided in the emitter (Rule 2).
  - **Predicate:** `ClassifyMembership` is the only place that decides either membership kind, and the emitter's `In` arm reads it; no type test is added in `CodeGen/`.
  - A reference payload records nothing: its `None` reaches the receiver's `Contains(null)`, which answers (D6).
  - **The literal `None`** (ruling A) gets no lowering. Into a non-optional slot it is SPY0222 at both arms; into an optional element it is plain membership, unchanged.
- **D2. Subsequence containers raise.** A container is a subsequence container when its CLR type (`BuiltinType.ClrType`, or `UserDefinedType.Symbol.ClrType` for `bytes`) has a public `Contains` that takes its own type (`string.Contains(string)`, `Bytes.Contains(Bytes)`). This is decided by CLR reflection through `ClrTypeHelper`, not by name (rung 3).
  - For such a container, any `NullableType` needle (value or reference payload) records `MembershipNoneRaises`.
  - The emitter emits `Builtins.ContainsNoneRaises(x, y, static (c, n) => c.Contains(n))`. Overloads for a value needle and a reference needle throw `TypeError` on `None`, with CPython's text (message is DEVIATION by default). This applies ruling 2.
  - **Predicate:** `x: str | None = None; x in "abc"` raises a TypeError that `except TypeError:` catches.
- **D3. The CLR-backed slot (#2647).** `ResolveMembershipElementType` (`:1617`) resolves the needle slots of a CLR-backed non-generic container from its public single-argument `Contains` overloads instead of returning none. The CLR arm at `:1684` matches only a `BuiltinType`; `bytes`, `IPv4Network`, `IPv6Network`, `Namespace` and `EmailMessage` are `UserDefinedType`s whose `Symbol.ClrType` carries the type, so the arm is extended to that case, read through `ClrTypeHelper`, and generalized from `FirstOrDefault` to the overload set (a needle is accepted when it is assignable to any overload's slot). It is a needle-type decision, not a name rule.
  - `bytes`' slots are `int` and `bytes` (ruling C); the spec row is amended (D5).
  - A needle no overload takes is refused with SPY0222 and its cast steer (`membership-needle-type-mismatch`); so is the literal `None` (ruling A).
  - **Predicate:** `n: int64 = 1; n in bytes([1])` and `"x" in IPv4Network("10.0.0.0/8")` are SPY0222, never SPY0908; `bytes([1]) in bytes([1, 2])` and `1 in bytes([1, 2])` still print `True`; `None in EmailMessage()` is SPY0222.
- **D4. Evaluation order.** Both helpers take the needle before the container, so lifted cells evaluate `x` then `y`, as Python does. This does **not** settle #2645: every non-lifted cell keeps `y.Contains(x)` (container first). #2645 stays open, and its cure can route the plain arm through the same helper shape.
- **D5. Spec.** In `docs/language_specification/membership_operators.md` › Needle Type, add a "None needles" paragraph. A `T | None` needle is accepted: `None` is no element's equal, TypeError for `str`/`bytes` (D2), the receiver's answer for a CLR container (D6). The literal `None` is refused unless the element type is optional (ruling A). Use executed examples whose output differs under the bug.
  - The Container kinds row for `bytes` reads `int` or `bytes` (subsequence test), per ruling C.
  - In `docs/deviations.yaml`, state that `membership-needle-type-mismatch` covers the literal `None` into a non-optional slot (ruling A) and not a `T | None` needle (rulings 1–2).
  - That row's rationale changes from "can never be a member" to ruling B's. The slot holds `int`, and a needle must convert implicitly to the slot type. This is a deliberate difference from Python (CPython: `True in range(3)` and `Decimal(1) in range(1, 3)` are True), and the cure is a cast. Its example names a `bool` or `decimal` needle.
- **D6. Receivers answer `None` as CPython does.** Rung 2, in Stdlib C#: `Counter.Contains(null)` returns `False`, and `IPv4Network.Contains`, `IPv6Network.Contains` and `EmailMessage.Contains` raise `AttributeError` on `null` (CPython's `None._ip` / `None.lower()`; message DEVIATION by default). `Namespace.Contains(null)` already returns `False`, as CPython. No checker or emitter change: the reference needle already reaches `Contains`.
  - **Predicate:** `a: IPv4Address | None = None; a in IPv4Network("10.0.0.0/8")` raises an `AttributeError` that `except AttributeError:` catches; `s: str | None = None; s in Counter[str](["a"])` prints `False`.
