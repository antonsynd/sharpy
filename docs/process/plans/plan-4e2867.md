# Optional-needle membership: `T | None in container`

## Context

#2635: a value-typed `T | None` needle is refused (SPY0222) by `in`/`not in`, where CPython 3.15 answers `False`/`True` for `None`. Found via `socket.error.errno: int | None` (PR #2636).

## Current State

Measured @ ef459621b (CPython 3.15.2, oracle required) by stage 0, `OptionalMembershipDifferentialTests`: 24 payloads, 20160 cases (10308 compared, 9852 hand-expected), 5052 divergent cells in 28 rows of `optional-membership-differential-allowlist.txt` (`<container>[OfOptional]/<Plain|NoneNeedle>`, each pinning its cells).

- Value payloads (`int8`…`uint64`, `float32/64`, `decimal`, `bool`, `bytes`, `tuple[int, int]`, a user `struct`) as `T | None`: SPY0222 in every element-typed container (14) and in `range`. An int-backed `enum` payload is SPY0908 there instead (CS1503 `Color?` → `Color`): `UserDefinedType.IsValueType` (`SemanticType.cs:490`) is false for an enum, so `NullableType.IsAssignableTo` (`:749`) admits `Color | None` into `Color`, as at a store (D7).
- The literal `None` into a non-optional slot: SPY0222 (ruling A), except the CLR-backed fixed-slot containers: SPY0908 in `bytes`, runs in argparse `Namespace` and `EmailMessage`, `NullReferenceException` in `IPv4Network`/`IPv6Network`.
- Reference payloads (`str`, class, interface, union, delegate, string-backed enum, IP addresses) as `| None` reach `Contains(null)`: `False` in the scan containers, `ArgumentNullException` in `Counter` and `str`, `NullReferenceException` in the IP networks, `False` in `EmailMessage` (CPython: `AttributeError` for these three, TypeError for `str`).
- CLR-backed non-generic containers (#2647: `bytes`, the IP networks, `Namespace`, `EmailMessage`) are registry `UserDefinedType`s (`TypeChecker.Expressions.Literals.cs:1005`) whose needle no arm of `ResolveMembershipElementType` decides: SPY0908 for every needle `Contains` cannot take.
- Out of contract: `Counter[T | None]` with a `None` element throws at construction (rows `CounterOfOptional/*`, #2651).

## Defect Class

- **Violated contract:** a `T | None` needle is decided like the `T` twin at every membership site, and its `None` answers what CPython answers: `False` for `in` in an equality scan, TypeError in `str`/`bytes`, the receiver's own answer elsewhere (`AttributeError` for an IP network or `EmailMessage`). Never SPY0222, SPY0908 or a CLR exception. The literal `None` is refused (SPY0222) unless the element type is optional (ruling A).

## Adversarial Review (pre-mortem)

- **Alternative root cause:** a store-seam rule. Discriminator: `b: bool = x in [1]` gives SPY0222 while `x == 1` runs, so the needle check (`ClassifyMembership`, `:1578`) refuses.
- **Alternative layer:** a Core `Contains(T?)` per receiver (rung 2) cannot reach user `__contains__` or the tuple projection, nor tell `string?` from `string`.
- **How the fix could be inert:** the emitter still prints `y.Contains(x)` (SPY0908); an enum needle passes assignability and skips D1 (D7, M6).
- **Before/after by direction:** newly refused: needles a CLR-backed `Contains` cannot take (SPY0908 → SPY0222) and the literal `None` into `Namespace`/`EmailMessage` (runs today; ruling A); D7's list. `b"a" in b"ab"`, `97 in b"ab"`, `str | None in str` keep running.
- **Blast radius:** Compiler.Tests (fixtures, Differential, GapDiscovery, InteropConformance, MetamorphicCorpus, the warm/cold harness), Stdlib.Tests, Cli.Tests, LSP `FrontEndParityTests`. D7 reaches every enum type; no harness generates enum × store site, so T6's by-direction list and the gate guard it (prototype: 83,352 tests reported before the 2-hour cap, failing only stage 0's `Color` pins and an oracle-without-`yaml` cell).
- **Generated artifacts touched:** spy-stdlib and spy-test C#, regenerated at T1 (expect no diff).

## Design Decisions

- **D1. Lift the value needle.** In `ClassifyMembership` (`TypeChecker.Expressions.Operators.cs:1578`), after D2's test and only after `IsArgumentAssignable(needleType, elementType)` fails, a `NullableType` needle whose underlying type `IsArgumentAssignable` to the slot is accepted. A needle the slot holds (`int | None` into `list[int | None]`) keeps the plain path; the `*OfOptional/Optional` cells pin that order.
  - For a non-subsequence container with a value payload, `ClassifyMembership` returns `OperatorLoweringKind.MembershipNoneIsFalse`; the binary site records it with `SetOperatorLowering` (`SemanticInfo.cs:2148`; `_operatorLowerings` is in `MergeFrom`, `:2514`), the chain site in its `ComparisonLinkLowering` (dead until #2648).
  - The emitter `In`/`NotIn` arm (`RoslynEmitter.Expressions.Operators.cs:186`) reads the kind and emits `Builtins.ContainsOptional(x, y, static (c, n) => c.Contains(n))`, negated for `not in`, container projected as today; the Core helper (beside `Map.cs`) is `needle.HasValue && contains(container, needle.Value)`, `T : struct`.
  - Rung 2 for the body (a CLR `Contains(T)` will not take a `T?`); the choice of helper is a checker fact (Rule 2).
  - **Predicate:** `ClassifyMembership` is the only place that decides either kind and the emitter's `In` arm reads it; no type test in `CodeGen/`.
  - A reference payload records nothing (D6). The literal `None` gets no lowering: SPY0222 into a non-optional slot, plain membership into an optional element.
- **D2. Subsequence containers raise.** A container is one when its CLR type (`BuiltinType.ClrType`, or `UserDefinedType.Symbol.ClrType` for `bytes`) has a public `Contains` taking its own type (`string.Contains(string)`, `Bytes.Contains(Bytes)`), read through `ClrTypeHelper` (rung 3).
  - Any `NullableType` needle (value or reference payload) whose underlying type the slot holds records `MembershipNoneRaises`, decided before `ClassifyMembership`'s early return on assignability (`str | None` passes that test into `str` today and must not keep the plain path).
  - The emitter emits `Builtins.ContainsNoneRaises(x, y, static (c, n) => c.Contains(n))`; its value and reference overloads throw `TypeError` on `None` (ruling 2).
  - **Predicate:** `x: str | None = None; x in "abc"` raises a TypeError that `except TypeError:` catches.
- **D3. The CLR-backed slot (#2647).** `ResolveMembershipElementType` (`:1617`) resolves a CLR-backed non-generic container's needle slots from its public single-argument `Contains` overloads. The CLR arm at `:1684` matches only a `BuiltinType`; it is extended to a `UserDefinedType` whose `Symbol.ClrType` carries the type (through `ClrTypeHelper`) and generalized from `FirstOrDefault` to the overload set (accepted when assignable to any overload's slot). Not a name rule.
  - `bytes`' slots are `int` and `bytes` (ruling C). A needle no overload takes is SPY0222 with its cast steer; so is the literal `None` (ruling A).
  - **Predicate:** `n: int64 = 1; n in bytes([1])` and `"x" in IPv4Network("10.0.0.0/8")` are SPY0222, never SPY0908; `bytes([1]) in bytes([1, 2])` and `1 in bytes([1, 2])` print `True`; `None in EmailMessage()` is SPY0222.
- **D4. Evaluation order.** Both helpers take the needle first, so lifted cells evaluate `x` then `y`, as Python does; non-lifted cells keep `y.Contains(x)` (#2645 stays open).
- **D5. Spec.** `membership_operators.md` › Needle Type gains a "None needles" paragraph: a `T | None` needle is accepted; `None` is no element's equal, TypeError for `str`/`bytes` (D2), the receiver's answer for a CLR container (D6); the literal `None` is refused unless the element type is optional (ruling A). Executed examples whose output differs under the bug.
  - The Container kinds row for `bytes` reads `int` or `bytes` (subsequence test), per ruling C.
  - `docs/deviations.yaml`: `membership-needle-type-mismatch` covers the literal `None` into a non-optional slot (ruling A), not a `T | None` needle (rulings 1–2); its rationale becomes ruling B's (a needle converts implicitly to the `int` slot; CPython: `True in range(3)` is True; cure: a cast), example a `bool` or `decimal` needle.
  - `enums.md`: an int-backed enum is a value type; `Color | None` needs narrowing or `??` where a `Color` is due (D7).
- **D6. Receivers answer `None` as CPython does.** Rung 2, Stdlib C#: `Counter.Contains(null)` returns `False`; `IPv4Network.Contains`, `IPv6Network.Contains` and `EmailMessage.Contains` raise `AttributeError` on `null` (CPython: `None.version`/`None.lower()`; message DEVIATION by default). `Namespace.Contains(null)` already returns `False`. No checker or emitter change.
  - **Predicate:** `a: IPv4Address | None = None; a in IPv4Network("10.0.0.0/8")` raises an `AttributeError` that `except AttributeError:` catches; `s: str | None = None; s in Counter[str](["a"])` prints `False`.
- **D7. Enums are value types (ruling E).** `UserDefinedType.IsValueType` (`SemanticType.cs:490`) is true for `TypeKind.Struct` and for `TypeKind.Enum` unless `Symbol.IsStringEnum` (a string-backed enum lowers to a class, enums.md; known from Pass 1). It stays the one place a user type's value-ness is decided; no caller changes. No ladder rung: it is the type's representation (a C# `enum` is a value type); keying D1 on the CLR representation was rejected, as the same wrong answer sits at every caller below.
  - Callers whose answer changes for an enum, by direction (a one-line prototype against the base c1a8c1149, `run`; no probe moved worked → refused): `NullableType.IsAssignableTo` (`:749`, #1399's store rule: argument, store, return, `append`, `dict.get`, a CLR `DayOfWeek` too) and `EraseNullableReferenceAnnotations` (`:79`, `list[Color]` ↔ `list[Color | None]`): SPY0908 → SPY0220/SPY0260/SPY0222. Variance (`TypeChecker.Utilities.cs:1537`, `list[Color]` into `IEnumerable[object]`): SPY0908 → SPY0220. `LoweringForRemoveNone` (`:859`) and the loose member arm (`TypeChecker.Expressions.Access.cs:272`): a narrowed `Color` argument or store, and `e.name`, SPY0908 → runs; `e.value` alone printed `Color.GREEN` (wrong), now `2`. `ClrSignatureKey` (`:58`): `f(Color)` beside `f(Color | None)` SPY0701 → runs. `CodeGenInfoComputer` (`:881`): `__eq__(self, other: Color)` SPY0908 → runs. Constraints (`GenericTypeInferenceService.cs:701/712`): inferred enum for `T: struct` SPY0237 → runs, for `T: class` SPY0908 → SPY0237. SPY0465 (`TypeChecker.Expressions.Operators.cs:322`): `c is d` on two enums now warns; it printed `False` before and after (CPython `True`: ledger cell). Unchanged: equality, `TypeSubstitution.cs:50`, `match`, `??`, a string-backed enum.
  - Ledger, outside this contract: a walrus-narrowed `Color` argument stays refused (SPY0908 → SPY0220, as `int` is today); `Box[Color]` with `T: class` stays SPY0908.
  - **Predicate:** `d: Color | None = Color.RED; g(d)` into `g(c: Color)` is SPY0220, never SPY0908; a string-backed `Tone | None` into `Tone` still runs.
