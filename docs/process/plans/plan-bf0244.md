7. **#1984 template-level order — the static walker stops at the first field it cannot decide.** `CheckStaticFormatTemplateArguments` walks holes in order; a hole with `ArgumentIndex == null` (keyword/attribute/index field) or `index >= positionalArguments.Count` (no spread) ENDS the walk (`break`, not `continue`); a refused spec reports and ends it. Consequence: `"{5}{0:=5}"` and `"{name}{0:=5}"` compile and raise the FIRST field's runtime error (python's first error); `"{0:=5}{5}"` is still SPY0609 (positive control). **Direction cell the `break` loses** [ADDED: verifier]: `"{name}{0:=5}".format("ab", name=1)` — python resolves `name` and raises `ValueError: '=' alignment…` on field 1 (verified), and today the static twin refuses it; a bare `break` at every keyword field turns that SPY0609 into a runtime `ValueError` (error → error, but a compile-time refusal weakened). The walker has the call's keyword arguments in scope: a keyword field whose name matches a keyword argument of the same call is DECIDED (continue), one that does not is where the walk ends. Record both cells in `FormatSpecStaticTwinRouteTests`. No new static refusal for out-of-range indexes or keyword fields (their python twins are `IndexError`/`KeyError`, not "invalid format specification"; a static twin for them is a separate cell to file, with the note that the runtime keyword message is `cannot use keyword arguments…` where python says `KeyError: 'name'`).
