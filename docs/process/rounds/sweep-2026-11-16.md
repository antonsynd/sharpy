## Limits

- About 8 cells were run per issue (about 20 on #2423 #2424 #2425). REPRODUCES and PARTIAL are verdicts on the cells run, not on every cell of a tracker.
- No test suite was run. A NOT_RUNNABLE row is a read of the tree (`git grep`), not a measurement.
- Interop issues that need Unity or another unavailable assembly were measured with stand-in assemblies; LSP issues were driven over `sharpyc lsp` stdio where the agent could, else read statically.
- 290 verdicts are high confidence, 56 medium. The seven FIXED verdicts were replayed by the lead, cell by cell, with the same results.
- Four issues quote a python result CPython 3.15.2 does not give: #2064 (no `NameError`: annotations are lazy), #2096, #2113 (`math` is built in, so python prints `2.0`), #2412 (`AttributeError` on the alias). None changes the ruled expectation; the issue text is what is wrong.
- The 11 issues labelled `parked` were not swept.

## Method

Fifteen agents, each with a slice of the issues in number order, the full issue text with every comment, and one brief: list the issue's cells, run the headline cell first, save each program, compare with the issue's stated right result and with CPython 3.15.2 where python is the standard, and write one verdict per issue. Agents were read-only on the repository and made no GitHub calls. Programs and per-cell records were kept in the session's scratch space and are not in the repository; the tables below are what survives.
