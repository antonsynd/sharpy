# Annotation-path vs expression-path agreement allowlist (ratchet ledger).
#
# One `producer::operation` cell key per line (see AnnotationExpressionPathAgreementTests).
# A cell whose two spellings reach different verdicts fails the ratchet UNLESS its key appears here.
# `#` starts a comment; blank lines are ignored.
#
# The contract: ONE RUNTIME TYPE HAS ONE SURFACE, HOWEVER THE TYPE SYSTEM ARRIVED AT IT. A value
# named by a type annotation and the same value produced by an expression are the same value; the
# annotation is a naming convenience, not a different type. Where the two disagree, at least one is
# wrong — and #1496 is the proof that they can be wrong in OPPOSITE directions at the same time
# (annotation accepted `x | y` and threw at runtime; the inline spelling refused it outright), so
# "the other spelling works" never establishes that a cell is fine.
#
# DO NOT DELETE THIS FILE. Its presence is what arms the ratchet; the sweep throws if it is missing
# rather than passing silently, so removing it cannot be mistaken for relaxing it.
#
# Rules for adding an entry:
#   1. It MUST cite a filed GitHub issue explaining the divergence the cell exposes.
#   2. It MUST correspond to a cell a real run confirms divergent — never allowlist speculatively.
#   3. It is temporary. Delete the line in the same change that fixes the bug ("drain on fix"). The
#      sweep FAILS on a stale entry — an allowlisted cell that has started agreeing — so draining is
#      part of landing the fix rather than a follow-up nobody schedules.
# Any growth is a regression in the contract, not a fact about the code that can be left standing.
