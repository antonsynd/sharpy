# #1147 (OPEN, NEW) — a parenthesized method-group callee with NO explicit type args is emitted as a C#
# CAST, not an invocation. `(identity)(5)` emits `(Identity)(5)`, which Roslyn parses as a cast to a
# type `Identity` → CS0246/CS0118/CS0426 (a csLeak: clean Sharpy analysis, uncompilable C#). Root
# cause: RoslynEmitter.GenerateCall (CodeGen/RoslynEmitter.Expressions.Access.cs:34-36) unwraps the
# `Parenthesized` wrapper into a local `callee` for the generic-instantiation (IndexAccess) detection
# only; the plain-identifier/member dispatch below (line 73 `call.Function is Identifier`, and the
# member-access arm) still tests the ORIGINAL `call.Function`, so a parenthesized method group with no
# `[T]` misses every proper arm and falls through to a verbatim `(Name)(args)` emit. This is the
# sibling gap to the #1138 fix (which unwrapped only the `(f[int])(x)` IndexAccess shape); class X1
# (semantics accepts, codegen emits uncompilable C#). A fix should retest the unwrapped `callee` for
# the identifier/member arms (or unwrap once at the top of GenerateCall). Confirmed NOT generic-specific:
# the two `nongeneric_*` cells below are a plain user fn `(foo)(5)` and a non-generic method

# selection by explicit type args) × X1 — value-argument validation is skipped once the type-arg count
# pins a multi-arity builtin overload.
